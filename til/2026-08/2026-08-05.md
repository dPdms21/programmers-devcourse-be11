## 오늘 배운 내용

오늘은 코딩 테스트 특강 문제를 풀며   
문자열의 단계별 변환, Comparator를 이용한 정렬 기준 정의, Set을 활용한 중복 검사, PriorityQueue를 이용한 상위 값 관리를 복습했다.

문자열 문제에서는 각 변환 단계를 순서대로 적용하고, 빈 문자열이나 마지막 인덱스처럼 예외가 발생할 수 있는 조건을 먼저 확인하는 것이 중요했다.

사용자 정의 정렬에서는 기준 문자가 다르면 해당 문자로 비교하고, 같으면 문자열 전체를 사전순으로 비교하도록 Comparator를 작성했다.

중복 검사에는 Set을 사용하고, 상위 `k`개의 값과 그중 최솟값을 계속 유지해야 하는 문제에는 최소 힙인 PriorityQueue를 활용했다.

## 실습 및 과제

> 신규 아이디 추천

문자열을 소문자로 변환한 뒤 허용되지 않는 문자를 제거하고, 연속된 마침표를 하나로 변경하는 단계를 순서대로 구현했다.

정규식 `[^a-z0-9_.-]`에서 대괄호 안 첫 위치의 `^`는 지정한 문자를 제외한다는 의미다. 대괄호 밖의 `^`는 문자열 시작, `$`는 문자열 끝을 의미한다.

`[.]{2,}`의 `{2,}`는 마침표가 두 번 이상 반복되는 경우를 의미하며, 최대 반복 횟수에는 제한이 없다.

문자열 처음과 끝의 마침표를 제거하고, 빈 문자열이면 `"a"`를 대입했다.   
마지막 문자를 확인할 때는 빈 문자열에서 `charAt()`을 호출하지 않도록 먼저 `isEmpty()`를 확인해야 했다.

`StringBuilder`도 `charAt()`으로 문자를 조회하고 `setCharAt()`으로 특정 위치의 문자를 변경할 수 있다.   
다만 순회 중인 같은 객체에 계속 `append()`하면 길이가 증가하므로, 기존 문자열을 기준으로 결과를 만들 때는 별도의 객체를 사용해야 한다.

> 문자열 내 마음대로 정렬하기

문자열 배열을 `n`번째 문자 기준으로 정렬하고, 문자가 같으면 문자열 전체를 사전순으로 정렬했다.

문자열의 특정 문자는 배열처럼 `a[n]`으로 접근하지 않고 `a.charAt(n)`을 사용해야 한다.

`Arrays.sort()`에 Comparator를 전달해 원본 배열을 직접 정렬했다.   
`Arrays.sort()`는 정렬된 배열을 반환하지 않으므로 정렬이 끝난 기존 배열을 그대로 반환해야 했다.

Comparator에서는 두 값의 순서에 따라 음수, `0`, 양수를 반환했다.   
기준 문자가 같은지는 `a.charAt(n) == b.charAt(n)`으로 확인하고, 같을 때는 `a.compareTo(b)`의 결과를 반환했다.

> 영어 끝말잇기

첫 번째 단어를 Set에 미리 저장한 뒤, 두 번째 단어부터 이전 단어의 마지막 문자와 현재 단어의 첫 문자를 비교했다.

현재 단어를 Set에 추가하기 전에 `contains()`로 중복 여부를 확인해야 했다. 먼저 추가하면 현재 단어가 항상 포함되어 있어 중복으로 판정된다.

탈락한 단어의 인덱스를 기준으로 참가자 번호는 `i % n + 1`, 진행 차례는 `i / n + 1`로 계산했다.

`HashSet`의 `add()`, `contains()`, `remove()`는 평균적으로 `O(1)`이므로 값의 순서가 필요하지 않고 중복 여부만 확인할 때 적합하다.

> 명예의 전당

상위 `k`개의 점수를 유지하면서 그중 최솟값을 확인하기 위해 PriorityQueue를 사용했다.

Java의 PriorityQueue는 기본적으로 최소 힙이므로 `peek()`는 현재 가장 작은 값을 조회하고, `poll()`은 가장 작은 값을 제거한다.

처음 `k`개의 점수는 모두 추가하고, 이후 점수가 현재 최솟값보다 크면 `poll()`로 최솟값을 제거한 뒤 새 점수를 추가했다.

매일 `peek()`로 현재 명예의 전당에 포함된 점수 중 최저 점수를 확인해 결과 배열에 저장했다.

## 헷갈렸던 점

`StringBuilder`도 `String`처럼 `charAt()`을 사용할 수 있는지 헷갈렸다.   
`StringBuilder`는 문자 조회와 변경이 모두 가능하지만, 순회 중 같은 객체에 값을 추가하면 길이가 달라질 수 있어 주의해야 했다.

정규식의 `^`는 항상 문자열 시작을 의미한다고 생각하기 쉬웠다.   
대괄호 밖에서는 문자열 시작이지만, 문자 집합의 첫 위치에서는 해당 문자들을 제외한다는 의미다.

`Arrays.sort()`의 반환값을 결과 배열에 대입하려 했지만, 이 메서드는 원본 배열을 직접 정렬하고 값을 반환하지 않는다.

영어 끝말잇기에서는 현재 단어를 Set에 추가하기 전에 중복 여부를 확인해야 했다. 검사보다 추가를 먼저 하면 모든 단어가 중복으로 처리된다.

PriorityQueue가 오름차순으로 전체 값을 정렬해 주는 배열이라고 생각하기보다,   
기본적으로 최솟값을 루트에서 빠르게 조회하고 제거할 수 있는 최소 힙이라는 점을 구분해야 했다.

## 오늘 느낀 점

문자열 문제는 사용한 메서드보다 변환 순서와 빈 문자열, 마지막 인덱스 같은 예외 조건을 정확하게 관리하는 것이 중요했다.

정렬 문제에서는 Comparator를 통해 문제에서 요구하는 우선순위를 직접 정의할 수 있었고, 기준값이 같을 때 적용할 두 번째 조건도 빠뜨리지 않아야 했다.

Set과 PriorityQueue는 각각 중복 확인과 최솟값 관리에 적합했다. 문제에서 반복적으로 필요한 연산이 무엇인지 확인한 뒤 선택해야 한다고 느꼈다.

오늘 특강 전체를 참여하지는 못했지만, 특강에서 다룬 네 문제를 직접 풀며 필요한 개념과 헷갈렸던 구현 부분을 정리했다.
