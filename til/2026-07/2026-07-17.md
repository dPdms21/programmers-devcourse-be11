## 오늘 배운 내용

오늘은 코딩테스트 문제를 풀면서 Java에서 문자열과 배열의 정렬 기준을 직접 정의하는 방법을 학습했다.

`Arrays.sort()`는 기본 오름차순 정렬뿐 아니라 `Comparator`를 전달해 원하는 기준으로 정렬할 수 있다.  
문자열의 특정 위치 문자를 먼저 비교하거나,   
두 값이 같을 때 문자열 전체를 다시 비교하는 것처럼 여러 정렬 조건을 순서대로 적용할 수 있다는 점을 확인했다.

`JadenCase 문자열 만들기`에서는 문자열을 순회하며 현재 문자가 단어의 첫 문자인지 판단하는 방식으로 대소문자를 변환했다.  
공백을 기준으로 다음 문자가 새 단어의 시작인지 상태값으로 관리하면, 연속된 공백을 유지하면서도 각 단어의 첫 문자만 대문자로 처리할 수 있다.

`H-Index`에서는 단순히 논문의 인용 횟수 중 하나를 답으로 고르는 것이 아니라,  
정렬된 배열의 현재 위치에서 앞으로 남은 논문 수를 기준으로 가능한 `h` 값을 판단해야 한다는 점을 정리했다.

강의에서는 Bubble Sort, Insertion Sort, Selection Sort, Quick Sort, Merge Sort의 동작 방식과 시간복잡도를 비교했다.  
정렬 알고리즘마다 구현 방식은 다르지만, 값을 비교해 정렬된 결과를 만든다는 공통 기능을 인터페이스로 추상화할 수 있다는 점도 확인했다.

## 실습 및 과제

> LMS w2 - 07 코딩테스트

문자열과 배열의 정렬 기준을 설정하는 문제를 풀이했다.

`문자열 내 마음대로 정렬하기`는 `Arrays.sort()`에 람다식으로 `Comparator`를 전달했다.  
두 문자열의 n번째 문자를 먼저 비교하고, 해당 문자가 같으면 `compareTo()`로 문자열 전체를 사전순 비교하도록 구성했다.

이를 통해 정렬 조건이 여러 개일 때는 우선순위가 높은 조건을 먼저 비교하고,  
같은 값이 나온 경우에만 다음 조건을 적용해야 한다는 점을 확인했다.

`JadenCase 문자열 만들기`는 문자열을 한 글자씩 순회하면서 단어의 첫 문자는 대문자로, 나머지 문자는 소문자로 변환했다.  
공백을 만나면 다음 문자를 단어의 시작으로 판단하고, 공백 자체는 그대로 결과에 추가해 원본 문자열의 공백 구조를 유지했다.

`H-Index`는 먼저 가능한 `h` 값을 하나씩 증가시키면서, 인용 횟수가 `h` 이상인 논문이 `h`편 이상인지 확인하는 방식으로 풀이했다.  
이후 인용 횟수 배열을 오름차순으로 정렬하고, 현재 위치부터 남은 논문의 수를 가능한 `h`로 보는 방식으로도 풀이했다.  
정렬된 배열에서 현재 논문의 인용 횟수가 남은 논문의 수 이상인 첫 지점을 찾으면 H-Index를 구할 수 있었다.

> LMS w2 - 07 정렬 알고리즘

Bubble Sort, Insertion Sort, Selection Sort, Quick Sort, Merge Sort의 핵심 동작을 정리했다.

Bubble Sort는 인접한 값을 비교해 잘못된 순서라면 교환하고, 큰 값을 뒤쪽으로 이동시킨다.  
Insertion Sort는 이미 정렬된 구간에 현재 값을 알맞은 위치로 삽입한다.  
Selection Sort는 정렬되지 않은 구간에서 최솟값을 찾아 현재 위치와 교환한다.

세 알고리즘은 구현이 비교적 단순하지만 평균과 최악 시간복잡도가 `O(n²)`이므로 데이터가 많을 때는 비효율적이다.

Quick Sort는 `pivot`을 기준으로 작은 값과 큰 값을 분리하고 각 그룹에 같은 과정을 재귀적으로 적용한다.  
평균 시간복잡도는 `O(n log n)`이지만, 분할이 한쪽으로 치우치면 최악의 경우 `O(n²)`이 될 수 있다.

Merge Sort는 데이터를 절반씩 나눈 뒤 정렬하면서 다시 병합한다.  
항상 `O(n log n)`의 시간복잡도를 유지하지만, 병합 과정에서 추가 공간이 필요하다.

정렬 기능은 `Sortable` 인터페이스로 추상화하고, 외부에서 `Comparator`를 전달해 정렬 기준을 변경할 수 있도록 구성했다.  
원본 리스트를 유지해야 할 때는 `new ArrayList<>(list)`로 복사본을 만든 뒤 정렬해야 한다는 점도 확인했다.

## 헷갈렸던 점

`문자열 내 마음대로 정렬하기`에서는 n번째 문자가 같은 경우를 어떻게 처리해야 하는지 헷갈렸다.  
n번째 문자만 비교하면 동일한 문자를 가진 문자열의 순서가 정해지지 않으므로,   
문자가 같을 때는 `compareTo()`로 문자열 전체를 다시 비교해야 한다.

`JadenCase 문자열 만들기`에서는 `split()`을 사용할 경우 연속된 공백이나 문자열 끝의 공백을 그대로 유지하기 어렵다는 점을 확인했다.   
문자열을 직접 순회하면서 다음 문자가 단어의 시작인지 상태로 관리하는 방식이 원본 공백을 유지하기에 적절했다.   
또한 단어의 첫 문자가 숫자여도 `Character.toUpperCase()`에 전달할 수 있으며, 숫자는 변환되지 않고 그대로 반환된다는 점을 확인했다.

`H-Index`에서는 처음에 가능한 `h`를 직접 증가시키며 조건을 확인했지만, 어떤 값을 기준으로 반복해야 하는지 헷갈렸다.  
두 번째 풀이에서는 배열을 정렬한 뒤 현재 위치부터 남은 논문의 수를 `h`로 보면 된다는 점을 이해했다.  
이를 통해 H-Index는 특정 논문의 인용 횟수를 그대로 답으로 정하는 것이 아니라,   
조건을 만족하는 논문의 수와 인용 횟수의 관계로 판단해야 한다는 점을 정리했다.

정렬 알고리즘에서는 Quick Sort와 Merge Sort가 모두 평균적으로 `O(n log n)`이지만 차이가 무엇인지 헷갈렸다.  
Quick Sort는 `pivot`과 데이터 배치에 따라 최악의 경우 `O(n²)`이 될 수 있고,   
Merge Sort는 항상 `O(n log n)`을 유지하는 대신 추가 공간이 필요하다.

## 오늘 느낀 점

정렬 문제는 단순히 `Arrays.sort()`를 사용하는 것보다 어떤 값을 먼저 비교하고,   
같은 경우 어떤 기준을 추가로 적용할지 정하는 것이 중요하다고 느꼈다.

특히 `Comparator`를 활용하면 문제에서 요구하는 복합 정렬 기준을 코드로 직접 표현할 수 있어,   
문자열이나 객체 정렬 문제에서 자주 활용할 수 있을 것 같다.

정렬 알고리즘을 비교하면서 모든 상황에서 가장 좋은 하나의 알고리즘이 있는 것이 아니라,  
데이터의 크기와 정렬 상태, 최악 시간복잡도, 추가 공간 사용 여부에 따라 적절한 방식을 선택해야 한다는 점을 이해했다.
