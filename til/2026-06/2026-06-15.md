## 오늘 배운 내용

오늘은 `Queue`, `PriorityQueue`, `Set`, `TreeSet`, `enum`을 실습하고,   
`HashMap`, 이진 검색 트리, `TreeMap`의 내부 동작을 직접 구현했다.

`forEach()`는 컬렉션의 요소를 하나씩 람다 표현식의 매개변수로 전달해 같은 작업을 수행하는 메서드다.  
객체를 정렬할 때는 `Comparator.comparing()`으로 문자열이나 객체 필드를 비교하고,   
`int` 값을 기준으로 비교할 때는 `Comparator.comparingInt()`를 사용할 수 있다.

`Set`은 중복을 허용하지 않으며, `add()`는 요소가 실제로 추가되면 `true`, 중복이라 추가되지 않으면 `false`를 반환한다.  
`TreeSet`은 중복을 허용하지 않으면서 요소를 자동으로 정렬하고, `first()`와 `last()`로 정렬된 첫 번째 값과 마지막 값을 가져올 수 있다.

`enum`은 사용할 수 있는 값을 미리 제한하는 타입이며, 필드와 생성자, 메서드도 가질 수 있다.  
`values()`는 정의된 모든 enum 상수를 배열로 반환한다.

## 실습 및 과제

> Java 컬렉션과 enum 실습

`PriorityQueue`에서 객체의 우선순위를 지정하는 방법으로 `Comparator.comparing()`과 `Comparator.comparingInt()`를 확인하고,   
익명 `Comparator`로 나이순·이름순 비교를 구현했다.

`PriorityQueue`를 향상된 for문이나 `Iterator`, `forEach()`로 순회하면 우선순위 순서가 보장되지 않고,   
우선순위대로 값을 확인하려면 `poll()`을 반복해야 한다는 점을 확인했다.
다만 `poll()`은 요소를 반환하면서 큐에서 실제로 제거한다.

`TreeSet`에서는 `first()`와 `last()`를 사용해 최솟값과 최댓값을 확인했다.  
변수 타입이 `Set<String>`이면 `TreeSet`에만 정의된 메서드를 바로 사용할 수 없으므로 다운캐스팅이 필요하고,   
처음부터 `TreeSet<String>`으로 선언하면 캐스팅 없이 사용할 수 있다.

`enum`에서는 `day`, `day.getDesc()`, `day.name()`의 차이를 정리했다.

* `day` -> enum 객체 자체
* `day.getDesc()` -> 직접 정의한 설명 필드
* `day.name()` -> enum 상수 이름을 문자열로 반환

> HashMap 직접 구현

배열과 단방향 연결 리스트를 이용해 해시맵을 직접 구현했다.

`hashCode()`는 객체를 해시 기반으로 구분하기 위한 `int` 값을 반환하고, 해시값을 배열 크기에 맞게 변환해 버킷 인덱스를 계산했다.

서로 다른 키가 같은 버킷 인덱스를 가지는 해시 충돌이 발생할 수 있기 때문에,   
같은 버킷에 노드를 연결 리스트 형태로 이어 붙이는 체이닝 방식을 사용했다.

`put()`에서는 같은 키가 있으면 값을 갱신하고, 새로운 키라면 버킷의 맨 앞에 노드를 연결했다.  
`get()`과 `containsKey()`에서는 버킷의 첫 노드만 확인하는 것이 아니라 `cur = cur.next`로 이동하며 정확한 키를 찾아야 했다.

새로운 키를 추가하기 전에 적재율을 확인하고, 기준에 도달하면 버킷 배열을 확장해 기존 노드를 다시 배치했다.  
이 과정에서 기존 연결을 잃지 않도록 `Node next = cur.next`로 다음 노드를 먼저 저장해야 한다는 점을 확인했다.

> Tree 직접 구현

이진 검색 트리의 삽입, 탐색, 순회 기능을 직접 구현했다.

삽입에서는 현재 노드와 한 번만 비교하는 것이 아니라, 값이 들어갈 빈 위치를 찾을 때까지 왼쪽 또는 오른쪽으로 재귀 호출해야 했다.

```java
node.left = insertNode(node.left, value);
node.right = insertNode(node.right, value);
```

재귀 호출이 끝난 뒤 `return node`를 통해 삽입이 완료된 서브트리의 루트를 부모 호출에 다시 연결했다.

전위, 중위, 후위 순회를 재귀로 구현했고, 레벨 순회는 `Queue`를 사용해 위층부터 왼쪽에서 오른쪽 순으로 방문하도록 구현했다.

반복문 전위 순회에서는 `Stack`의 후입선출 특성 때문에 오른쪽 자식을 먼저 넣고 왼쪽 자식을 나중에 넣어야 왼쪽 노드부터 방문할 수 있었다.  
반복문 중위 순회에서는 `Stack`을 왼쪽으로 내려가는 동안 부모 노드를 저장하는 용도로 사용했다.

> TreeMap 직접 구현

키와 값을 저장하는 이진 검색 트리 기반 `TreeMap`을 직접 구현했다.

문자열 키는 `compareTo()` 결과에 따라 왼쪽 또는 오른쪽에 배치하고, 같은 키가 들어오면 새 노드를 만들지 않고 기존 값을 갱신했다.

중위 순회를 사용하면 키를 입력 순서와 관계없이 정렬된 상태로 확인할 수 있었다.  
`firstKey()`는 루트부터 왼쪽 끝까지 이동한 키이고, `lastKey()`는 오른쪽 끝까지 이동한 키로 구현했다.

삭제에서는 자식이 없는 경우, 자식이 하나인 경우, 자식이 둘인 경우를 나누어 처리했다.  
자식이 둘인 노드는 오른쪽 서브트리에서 가장 작은 노드를 찾아 현재 노드의 키와 값으로 교체한 뒤, 오른쪽 서브트리에서 대체 노드를 삭제했다.

## 헷갈렸던 점

`Set.add()`가 단순히 값을 추가하는 메서드라고 생각했지만, 실제로는 추가 성공 여부를 `boolean`으로 반환한다는 점을 다시 확인했다.

`TreeSet`의 `first()`와 `last()`도 실제 객체가 `TreeSet`이라고 해서 항상 호출할 수 있는 것은 아니었다.  
변수 타입이 `Set<String>`이면 `Set`에 정의된 메서드만 사용할 수 있으므로,   
`TreeSet` 전용 메서드를 사용하려면 다운캐스팅하거나 변수 타입을 처음부터 `TreeSet<String>`으로 선언해야 했다.

`enum`에서는 객체 자체를 출력하는 `day`, 직접 만든 설명을 반환하는 `day.getDesc()`,   
상수 이름을 문자열로 반환하는 `day.name()`의 차이가 헷갈렸다.

HashMap 구현에서는 `Node cur = buckets[index]`가 새 키를 저장하는 코드가 아니라,   
해당 버킷의 첫 번째 노드를 가리키는 코드라는 점이 헷갈렸다.  
해시 충돌이 발생해도 인덱스만으로 값을 찾는 것이 아니라, 버킷의 연결 리스트를 순회하며 `equals()`로 정확한 키를 찾아야 했다.

트리 삽입에서는 재귀 호출 후 왜 `return node`가 필요한지 이해하는 데 시간이 걸렸다.  
새 노드를 만든 뒤 부모의 `left` 또는 `right`에 다시 연결하려면 각 재귀 호출이 현재 서브트리의 루트를 반환해야 한다는 점을 정리했다.

반복문 순회에서는 `Stack`이 단순히 방문 순서를 거꾸로 저장하는 것이 아니라,   
아직 처리하지 않은 부모 노드를 임시로 보관하는 역할도 한다는 점이 헷갈렸다.

## 오늘 느낀 점

컬렉션을 사용하는 것과 내부 구조를 직접 구현하는 것은 차이가 컸다.

`HashMap`은 배열만 사용하는 것이 아니라 해시 충돌을 처리하기 위한 연결 리스트와 용량 확장 과정이 필요했고,   
트리는 재귀 호출이 돌아오면서 노드가 다시 연결되는 흐름을 이해해야 했다.

특히 `HashMap`과 `TreeMap`이 모두 key와 value를 저장하지만,   
`HashMap`은 해시값과 버킷을 사용하고 `TreeMap`은 키 비교를 통한 이진 검색 트리 구조를 사용한다는 차이를 직접 구현하며 확인할 수 있었다.
