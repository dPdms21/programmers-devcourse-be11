## 오늘 배운 내용

오늘은 LMS에서 인터페이스, 중첩 클래스, 익명 클래스, 예외 처리를 학습하고,   
Java 컬렉션을 중심으로 `List`, `LinkedList`, `Stack`, `Map`, `HashMap`, `TreeMap`을 실습했다.
  
인터페이스의 `default` 메서드는 구현 객체로 호출하고, `static` 메서드는 인터페이스 이름으로 호출한다.  
또한 Java 9부터는 인터페이스 내부에서 공통 로직을 분리하기 위한 `private` 메서드도 사용할 수 있다는 점을 확인했다.

중첩 클래스에서는 내부 클래스에서 바깥 클래스의 멤버를 사용할 때 `OuterClass.this`처럼 바깥 객체를 명시해서 접근할 수 있다는 점을 확인했다.
  
익명 클래스는 이름이 없는 일회용 클래스로, 인터페이스나 추상 클래스를 한 번만 구현해서 사용할 때 `new 인터페이스명() { ... }` 형태로 작성할 수 있다.

예외 처리에서는 `try-catch`와 `throws`를 사용했다.  
`ArithmeticException`은 unchecked exception이라 반드시 `throws`가 필요한 것은 아니지만,   
문제 요구사항에 따라 메서드 선언부에 명시할 수 있다는 점을 확인했다.

`List`는 순서가 있고 중복을 허용하며 인덱스로 접근할 수 있는 컬렉션이고,   
`ArrayList`는 배열 기반이라 조회가 빠르지만 중간 삽입·삭제는 상대적으로 느리다는 점을 확인했다.  
`LinkedList`는 노드가 서로 연결된 구조라 삽입·삭제에 유리하지만, 인덱스로 접근할 때는 `ArrayList`보다 비효율적일 수 있다는 점을 정리했다.

`Stack`은 후입선출 구조로 `push()`, `pop()`, `peek()`, `empty()`를 사용해 값을 넣고 꺼내는 방식을 실습했다.    
`Map`은 key와 value를 한 쌍으로 저장하며, key는 중복될 수 없고 같은 key를 다시 넣으면 기존 value가 덮어씌워진다는 점을 확인했다.

`HashMap`은 순서를 보장하지 않지만 빠른 조회에 적합하고, `TreeMap`은 key 기준으로 자동 정렬된다는 차이도 학습했다.

## 실습 및 과제

> Java 컬렉션 실습

`ArrayList`, `LinkedList`, `Stack`, `HashMap`, `TreeMap`의 사용 흐름을 실습했다.

`Iterator`와 `ListIterator`를 사용해 컬렉션을 순회하는 방법을 확인했고,   
`ListIterator`는 정방향뿐만 아니라 역방향 순회도 가능하다는 점을 정리했다.  
`Map`에서는 `keySet()`, `values()`, `entrySet()`을 사용해 key, value, key-value 쌍을 각각 꺼내는 방식을 연습했다.

> ArrayList 구현

배열을 이용해 `ArrayList`의 기본 동작을 직접 구현했다.

내부 배열 `arr`과 현재 데이터 개수를 나타내는 `size`를 분리해서 관리했고,   
`addLast`, `addFirst`, `get`, `size`, `insert`, `remove` 메서드를 구현했다.  
배열이 가득 찼을 때는 `Arrays.copyOf(arr, arr.length * 2)`를 사용해 용량을 늘렸다.

`addFirst`와 `insert`에서는 요소를 오른쪽으로 밀 때 뒤에서부터 이동해야 하고,   
`remove`에서는 삭제한 위치 뒤의 요소들을 앞으로 당겨야 한다는 점을 확인했다.

> LinkedList 구현

이중 연결 리스트 구조를 직접 구현했다.

각 노드는 `data`, `prev`, `next`를 가지고, 리스트는 첫 노드를 가리키는 `head`,   
마지막 노드를 가리키는 `tail`, 현재 노드 개수인 `size`를 관리하도록 작성했다.  
`addFirst`, `addLast`, `insert`, `remove`를 구현하면서 노드끼리 연결하는 작업과 `head`, `tail` 포인터를 갱신하는 작업을 구분해서 정리했다.

삭제 구현에서는 맨 앞, 맨 뒤, 중간 삭제를 나누어 처리했다.  
특히 맨 앞 노드를 삭제할 때는 `head`를 단순히 `null`로 만드는 것이 아니라 다음 노드로 옮기고,   
새 `head.prev`를 `null`로 끊어야 한다는 점을 확인했다.

## 헷갈렸던 점

`Iterator`에서 `next()`가 왜 첫 번째 값을 건너뛰지 않는지 헷갈렸다.

처음에는 커서가 0번 요소에 있다고 생각했지만, 실제로는 0번 요소 앞에 있다고 보면 된다.  
그래서 첫 번째 `next()`는 0번 요소를 반환하고, 이후 커서가 다음 위치로 이동한다는 점을 정리했다.

`ListIterator`의 역방향 순회도 헷갈렸다.  
정방향은 `hasNext()`와 `next()`를 사용하지만, 역방향은 `hasPrevious()`와 `previous()`를 사용해야 한다.   
이전 값을 꺼낼 때는 `next()`가 아니라 `previous()`를 사용해야 한다는 점을 확인했다.

`removeLast()`가 안 된 이유도 다시 정리했다.  
실제 객체가 `LinkedList`여도 변수 타입이 `List`이면 `List`에 정의된 메서드만 사용할 수 있으므로,   
`removeLast()`를 사용하려면 변수 타입을 `LinkedList`로 선언해야 했다.

배열 기반 리스트에서는 `arr.length`와 `size`의 차이가 헷갈렸다.  
`arr.length`는 배열의 전체 용량이고, `size`는 실제 저장된 데이터 개수이므로 데이터 접근이나 출력 기준은 `size`를 사용해야 했다.

연결 리스트에서는 노드끼리 연결하는 것과 `head`, `tail` 포인터를 갱신하는 것이 별개의 작업이라는 점이 헷갈렸다.  
특히 삭제할 때는 연결을 끊는 순서와 `NullPointerException`이 발생하지 않도록 조건을 나누는 것이 중요했다.

향상된 for문도 다시 확인했다.  
`for (int value : arr)`에서 `value`는 인덱스가 아니라 배열 안의 실제 값이므로 `arr[value]`처럼 접근하면 안 되고,   
`value` 자체를 사용해야 한다는 점을 정리했다.

## 오늘 느낀 점

컬렉션을 직접 사용하는 것과 직접 구현하는 것은 난이도가 다르게 느껴졌다.

`ArrayList`는 내부적으로 배열과 `size`를 따로 관리해야 하고,   
`LinkedList`는 노드의 연결 방향과 `head`, `tail` 갱신을 함께 생각해야 해서 구조를 머릿속으로 따라가는 연습이 필요했다.  
특히 삽입과 삭제는 단순히 값을 넣고 빼는 것이 아니라, 기존 데이터의 위치나 노드 연결을 어떻게 바꿀지 먼저 생각해야 한다는 점을 느꼈다.

문제를 풀 때도 문장을 정확히 읽는 것이 중요하다고 느꼈다.  
기초 문제라도 헷갈린 부분은 기록하되, 굳이 로컬에 저장하지 않아도 된다고 판단했다.
