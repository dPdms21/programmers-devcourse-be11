# 2026-06-07 TIL (Today I Learned)

## 오늘 배운 내용

오늘은 CPU, 메모리, 레지스터의 동작 흐름을 정리했다.

CPU는 메모리에 저장된 명령어와 데이터를 읽고, 필요한 값을 레지스터에 적재한 뒤 연산을 수행한다.  
프로그램이 실행될 때 명령어와 데이터가 메모리에 올라가고, CPU가 이를 가져와 해석한 뒤 레지스터 값을 기준으로 연산한다는 흐름을 학습했다.

또한 컬렉션 기반 가계부 과제의 도전 과제를 이어서 구현했다.  
기존 가계부 프로그램에 날짜 역순 정렬, 월별 지출 합계, 금액 수정 기능을 추가하면서 `Map`, `List`, 객체, 메서드 분리 구조를 다시 연습했다.

## 실습 및 과제

> CPU와 메모리 동작 과정 정리

운영체제 학습 내용으로 CPU가 메모리의 값을 어떻게 읽고, 레지스터에 적재한 뒤 연산하는지 정리했다.

단순히 CPU가 연산을 수행한다고만 이해하는 것이 아니라, 메모리에서 명령어와 데이터를 가져오고, 필요한 값을 레지스터에 올린 뒤 연산 결과를 다시 레지스터나 메모리에 저장하는 흐름으로 정리했다.

> 컬렉션 기반 가계부 도전 과제

가계부 과제의 도전 과제를 구현했다.

기존에는 날짜별 지출 내역을 저장하고 조회, 삭제하는 기능을 구현했는데, 오늘은 추가로 날짜가 최신순으로 출력되도록 정렬 방식을 수정했다.  
이를 위해 기존 `HashMap` 대신 `TreeMap<>(Collections.reverseOrder())`를 사용해 날짜 키가 역순으로 관리되도록 변경했다.

또한 특정 날짜의 지출 내역을 조회할 때 해당 날짜의 합계뿐만 아니라, 같은 월에 해당하는 전체 지출 합계도 함께 계산하도록 기능을 추가했다.  
날짜 문자열에서 `yyyy-MM` 부분을 가져오고, `startsWith()`를 사용해 같은 월의 날짜를 찾아 합계를 구했다.

마지막으로 기존 지출 항목의 금액을 수정하는 기능을 추가했다.  
수정할 날짜를 입력받고, 해당 날짜의 항목 목록을 출력한 뒤, 수정할 번호와 새 금액을 입력받아 `Item` 객체의 금액을 변경하도록 구현했다.

## 헷갈렸던 점

가계부 도전 과제를 하면서 `Map`의 정렬 방식이 헷갈렸다.

처음에는 `HashMap`에 저장된 날짜 목록을 따로 `List`로 꺼낸 뒤 정렬하는 방식으로 생각했는데, 날짜 키 자체를 정렬된 상태로 관리하려면 `TreeMap`을 사용할 수 있다는 점을 다시 확인했다.  
특히 최신 날짜가 먼저 나오게 하려면 `Collections.reverseOrder()`를 함께 사용해야 했다.

월별 합계를 구하는 과정에서는 날짜 문자열을 어떻게 활용할지 고민했다.  
`2026-06-07` 같은 문자열에서 앞의 `2026-06`만 잘라 같은 월인지 비교해야 했고, `substring()`과 `startsWith()`를 함께 사용해 처리했다.

금액 수정 기능에서는 `List<Item>`에서 특정 인덱스의 객체를 꺼내 값을 바꾸는 흐름을 다시 연습했다.  
사용자는 1번부터 번호를 입력하지만, 실제 리스트 인덱스는 0부터 시작하기 때문에 `num - 1`로 접근해야 한다는 점도 주의해야 했다.

또한 금액 수정이 가능하려면 `Item` 클래스에 `setPrice()` 메서드가 필요했다.  
객체의 값을 직접 바꾸는 기능을 추가할 때는 필드, getter, setter 구조도 함께 생각해야 한다는 점을 다시 확인했다.

## 오늘 느낀 점

CPU가 메모리와 레지스터를 거쳐 어떻게 명령어를 실행하는지 흐름으로 정리하니 훨씬 이해하기 쉬웠다.

가계부 과제도 기본 기능에서 끝내지 않고 도전 과제를 추가하면서 컬렉션을 실제 프로그램 기능에 어떻게 연결하는지 조금 더 익숙해졌다.  
특히 정렬, 합계 계산, 값 수정처럼 데이터를 저장한 뒤 활용하는 기능을 구현하면서 `Map`과 `List` 구조를 반복해서 연습할 수 있었다.
