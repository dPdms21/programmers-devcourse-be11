## 오늘 배운 내용

오늘은 JDBC를 이용해 Java 프로그램과 MySQL을 연결하고, SQL을 통해 회원 정보를 저장·조회·수정·삭제하는 흐름을 실습했다.

`DriverManager.getConnection()`으로 데이터베이스 연결을 생성하고, 연결 정보는 `.env`에서 읽도록 분리했다.  
`.env`는 Java가 자동으로 읽지 않으므로 `java-dotenv` 의존성과 `Dotenv.load()`가 필요했다.

`PreparedStatement`는 `Connection` 객체에서 생성하며,   
SQL의 값 부분을 `?`로 작성한 뒤 `setString()`, `setInt()` 등으로 값을 설정한다.

데이터를 변경하는 `INSERT`, `UPDATE`, `DELETE`는 `executeUpdate()`를 사용하고, 조회하는 `SELECT`는 `executeQuery()`를 사용한다.  
조회 결과는 `ResultSet`으로 받으며, 값을 꺼내기 전에 반드시 `next()`를 호출해야 한다.

데이터베이스 강의에서는 `GROUP BY`, `JOIN`, 서브쿼리, DML, 제약조건, 트랜잭션 등 기존 SQL 문법을 다시 정리했다.  
`WHERE 1 <> 1`을 사용하면 데이터 없이 테이블 구조만 복사할 수 있고,   
`DATE_ADD()`를 사용하면 기준 날짜에 기간을 더할 수 있다는 점도 확인했다.

## 실습 및 과제

> JDBC CRUD 실습

IntelliJ Database 도구에서 MySQL 연결을 확인하고, Java 코드에서 `member` 테이블을 대상으로 CRUD를 구현했다.

회원 추가는 `INSERT`, 전체·단건 조회는 `SELECT`, 회원 수정은 `UPDATE`, 회원 삭제는 `DELETE`를 사용했다.  
`WHERE` 조건을 생략하면 여러 행이 변경될 수 있으므로 수정과 삭제 대상은 반드시 조건으로 지정해야 했다.

`PreparedStatement`의 `?`에 값을 바인딩해 문자열 연결 방식보다 자료형을 안전하게 처리하고 SQL Injection 위험을 줄였다.

`executeUpdate()`의 반환값은 영향을 받은 행의 개수이므로, 반환값이 `0`보다 큰지 확인해 실제 변경 여부를 판단했다.

전체 조회에서는 `while (resultSet.next())`를 사용하고, 한 건 조회에서는 `if (resultSet.next())`를 사용했다.

`Connection`, `PreparedStatement`, `ResultSet`은 `try-with-resources`로 관리해 사용이 끝난 뒤 자동으로 닫히도록 했다.

> 회원 관리6 구현

기존 파일 입출력 기반 회원 관리 프로그램을 JDBC와 MySQL을 사용하는 구조로 변경했다.

기존 `List<Member>`, `save()`, `load()`를 제거하고, 필요한 시점마다 SQL을 실행해 회원 정보를 직접 조회하고 변경하도록 구현했다.

회원 추가와 수정, 삭제는 각각 `INSERT`, `UPDATE`, `DELETE`로 처리했다.  
이메일 조회, 이름 조회, 전체 조회는 `SELECT`를 사용했고, 현재 회원 수와 이메일 중복 여부는 `SELECT COUNT(*)`로 확인했다.

조회한 `ResultSet`은 별도의 변환 메서드에서 `Member` 객체로 변환했다.  
`grade` 값이 `VIP`이면 `VipMember`, 그 외에는 `NormalMember`를 생성하도록 구성했다.

회원 수정은 메모리의 객체 필드를 변경하는 방식이 아니라 `MemberManager.update()`에서 `UPDATE` SQL을 실행하도록 변경했다.  
반면 `printInfo()`는 조회 결과를 출력할 때 계속 사용하므로 유지했다.

이메일 컬럼에는 `UNIQUE`, 필수 컬럼에는 `NOT NULL` 제약조건을 설정해 Java 코드뿐 아니라 데이터베이스에서도 잘못된 데이터가 저장되지 않도록 했다.

> 데이터베이스 강의 정리

테이블 저장 엔진을 지정하는 `ENGINE=InnoDB`와 트랜잭션·외래 키 지원 특징을 정리했다.

`INSERT INTO ... SELECT ...`에서는 원본과 대상 테이블의 구조가 같아도 컬럼 목록을 명시하는 편이 구조 변경에 안전하다는 점을 확인했다.

`WHERE 1 <> 1`은 항상 거짓이므로 기존 데이터는 제외하고 테이블 구조만 복사할 때 사용할 수 있다.

`DATE_ADD(HIREDATE, INTERVAL 90 DAY)`처럼 날짜에 기간을 더할 수 있으며, 날짜를 빼는 경우에는 `DATE_SUB()`를 사용할 수 있다.

## 헷갈렸던 점

`prepareStatement()`를 단독으로 호출하려 했지만, 이 메서드는 `Connection` 객체에서 호출해야 했다.

```java
PreparedStatement ps = conn.prepareStatement(sql);
```

`ResultSet`은 생성 직후 첫 번째 행을 가리키는 것이 아니라 첫 번째 행 앞에 위치한다.  
따라서 `getString()`이나 `getInt()`를 호출하기 전에 `rs.next()`로 행을 이동해야 했다.

`try-with-resources`에서는 `Connection`, `PreparedStatement`, `ResultSet`을 하나의 괄호 안에서 세미콜론으로 구분해야 했다.

```java
try (
        Connection conn = connection();
        PreparedStatement ps = conn.prepareStatement(sql);
        ResultSet rs = ps.executeQuery()
) {
}
```

## 오늘 느낀 점

파일 입출력 방식에서는 회원 목록 전체를 메모리에 올리고 파일을 다시 저장했지만,   
JDBC 방식에서는 필요한 시점마다 SQL을 실행해 데이터를 직접 조회하고 변경한다는 차이를 확인했다.

JDBC 코드는 SQL만 작성하는 것이 아니라 `Connection`, `PreparedStatement`, `ResultSet`의 생성 순서와 자원 해제까지 함께 관리해야 했다.

조회 결과를 객체로 변환하는 메서드를 분리하니 SQL 처리 코드와 객체 생성 코드의 역할이 명확해졌다.
