## 오늘 배운 내용

오늘은 Java 객체지향 part2 내용을 중심으로 생성자, 상속, 오버라이딩, 캡슐화, 접근 제어자를 학습했다.

생성자 오버로딩과 `this()`, `super()`를 통해 객체 초기화 흐름을 확인했고,   
부모 클래스의 필드와 메서드를 자식 클래스에서 어떻게 활용하는지 정리했다.
또한 `private` 필드는 외부에서 직접 접근할 수 없으므로 getter/setter를 통해 값을 다루는 방식을 확인했다.

추가로 `Object` 클래스의 `toString()`, `equals()`, `getClass()` 메서드 역할을 살펴봤고,   
운영체제에서는 CPU 스케줄링과 프로세스 우선순위 개념을 정리했다.

## 실습 및 과제

> Java 객체지향 실습

생성자, 상속, 오버라이딩, 캡슐화, 접근 제어자 관련 실습을 진행했다.

카드 덱 예제를 통해 클래스, 객체 배열, 생성자, `toString()` 오버라이딩, 셔플 로직을 구현했다.  
또한 도형 예제를 통해 `Shape`를 상속한 `Circle`, `Triangle`이 각각 `draw()`를 오버라이딩하는 구조를 확인했다.

이 과정에서 상속 관계뿐만 아니라, `Point` 객체를 이용한 포함 관계도 함께 확인했다.

> 회원 관리 캡슐화 리팩토링

기존 회원 관리 과제를 캡슐화 구조에 맞게 리팩토링했다.

회원 정보를 직접 배열로만 다루는 것이 아니라, 회원 데이터를 객체로 분리했다.  
외부에서는 getter/setter를 통해 필요한 값에 접근하도록 하면서, 객체가 자신의 데이터를 관리하는 구조를 연습했다.

> 반려동물 키우기 게임 과제

반려동물 키우기 게임 과제를 구현했다.

반려동물 객체가 이름, 상태, 수치 같은 정보를 가지도록 구성하고, 사용자의 선택에 따라 먹이 주기, 놀아주기 등 상태가 변하는 흐름을 구현했다.  
객체의 필드와 메서드를 활용해 게임 상태를 관리하면서 캡슐화와 객체 상태 변경 흐름을 연습했다.

> 텍스트 RPG 전투 과제

객체지향과 생성자 개념을 활용해 텍스트 RPG 전투 과제를 구현했다.

`Character` 클래스를 기준으로 이름, 체력, 공격력을 가진 용사와 몬스터 객체를 만들고, 생성자를 통해 각 객체의 초기값을 설정했다.   
또한 `attack()`, `takeDamage()`, `isAlive()`, `showStatus()` 메서드를 사용해 공격, 피해 처리, 생존 여부 확인, 상태 출력 흐름을 구현했다.

기본 전투는 용사와 몬스터가 번갈아 공격하고, 한쪽의 체력이 0이 되면 전투가 종료되도록 구성했다.  
이후 몬스터 여러 마리를 배열로 관리하여 슬라임, 고블린, 드래곤을 순서대로 상대하도록 만들었다.

생성자 오버로딩과 `this()`를 사용해 이름만 입력하면 기본 능력치를 가진 몬스터가 생성되고,   
이름·체력·공격력을 모두 입력하면 커스텀 몬스터가 생성되도록 구현했다.  
추가로 `Hero`, `Monster`, `Dragon` 클래스로 구조를 확장하고, 공격, 방어, 회복 선택지를 추가해 사용자의 선택에 따라 전투 흐름이 달라지도록 기능을 보완했다.

## 헷갈렸던 점

오늘은 객체 배열과 참조 타입의 흐름이 헷갈렸다.

`Card2[] cards`에서 `cards[i]`는 `Card2` 객체 하나라는 점을 다시 정리했다.  
그래서 `shuffle()`에서 두 카드의 위치를 바꿀 때 `int temp`가 아니라 `Card2 temp`를 사용해야 했다.

`pick(int idx)`에서 `return pick(idx)`를 쓰면 자기 자신을 계속 호출하는 무한 재귀가 된다는 점도 확인했다.

캡슐화 구조로 리팩토링하면서 어떤 필드를 `private`으로 감추고, 어떤 값은 getter/setter로 열어야 하는지도 고민이 필요했다.  
코드는 읽으면 이해되지만, 처음부터 클래스 역할과 객체 구조를 직접 설계하는 것은 아직 어렵다고 느꼈다.

## 오늘 느낀 점

객체지향 코드는 단순히 문법을 아는 것보다 클래스 간 역할과 관계를 먼저 파악하는 것이 중요하다고 느꼈다.

오늘은 실습뿐만 아니라 회원 관리, 반려동물 게임, 텍스트 RPG 과제에서도 캡슐화와 상속 구조를 직접 적용해보면서   
객체가 상태를 가지고 동작하는 흐름을 더 많이 연습할 수 있었다.
상속, 포함 관계, 오버라이딩이 같이 나오면 복잡해 보이지만, 각 클래스가 어떤 역할을 맡는지 나누어 보면 구조가 조금씩 보였다.
