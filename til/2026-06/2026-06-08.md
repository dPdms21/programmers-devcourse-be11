## 오늘 배운 내용

오늘은 Java 배열과 문자열을 중심으로 실습을 진행했다.

배열을 사용해 여러 값을 하나의 구조로 관리하는 방법을 연습했고,   
문자열에서는 `String` 클래스의 특징과 `charAt()`, `substring()`, `split()` 같은 주요 메서드 사용 흐름을 확인했다.

운영체제 개념으로는 프로세스와 스레드를 학습했다.

## 실습 및 과제

> Java 배열과 문자열 실습

Java 기본 문법 실습으로 배열과 문자열 관련 예제를 작성했다.

배열 실습에서는 같은 타입의 여러 값을 하나의 변수로 관리하고, 인덱스를 통해 각 요소에 접근하는 방법을 연습했다.

문자열 실습에서는 `charAt()`, `substring()`, `split()` 메서드를 실습했다.  
`charAt()`으로 문자열의 특정 위치 문자를 꺼내고, `substring()`으로 문자열의 일부를 추출하며,   
`split()`으로 특정 구분자를 기준으로 문자열을 배열로 나누는 흐름을 확인했다.

> 2차원 배열 기반 회원 관리 과제

2차원 배열을 활용해 회원 관리 과제를 구현했다.

회원 정보를 이름, 나이, 전화번호처럼 여러 항목으로 관리해야 했기 때문에 2차원 배열을 사용했다.  
회원 추가, 전체 조회, 이름 기반 조회, 수정, 삭제, 중복 이메일 검사 흐름을 구현했다.

회원 데이터는 배열의 전체 크기와 실제 등록된 회원 수가 다르기 때문에 `memberCnt`를 따로 관리했다.  
또한 이름 조회 시 동명이인이 있을 수 있으므로, 조건에 맞는 회원을 하나만 찾고 끝내지 않고 배열을 끝까지 탐색하도록 개선했다.

> 2차원 배열 기반 빙고 게임 과제

2차원 배열을 활용해 빙고 게임을 구현했다.

사용자와 컴퓨터의 빙고판을 각각 2차원 배열로 만들고, 선택된 숫자는 별도의 체크 배열을 사용해 관리했다.  
빙고판 생성, 숫자 선택, 선택된 숫자 표시, 빙고 줄 수 계산, 승패 판정 흐름을 구현했다.

추가로 목표 빙고 줄 수와 빙고판 크기를 사용자가 직접 선택할 수 있도록 개선했다.  
고정된 크기와 목표 줄 수를 사용하는 구조에서 입력값에 따라 배열 크기와 최대 숫자가 달라지도록 수정했다.

## 헷갈렸던 점

회원 관리 과제에서는 `members.length`와 `memberCnt`의 차이가 헷갈렸다.

배열의 전체 크기는 요금제에 따라 정해지지만, 실제 등록된 회원 수는 그보다 적을 수 있다.  
따라서 조회, 수정, 삭제, 중복 이메일 검사는 배열 전체 길이가 아니라 실제 등록된 회원 수인 `memberCnt`까지만 반복해야 한다는 점을 정리했다.

회원 삭제 로직도 다시 생각할 필요가 있었다.  
삭제할 칸만 비우는 것이 아니라, 뒤에 있는 회원 정보를 한 칸씩 앞으로 당기고 마지막에 남은 데이터는 `null`로 정리해야 했다.

이름 조회에서는 동명이인이 있을 수 있기 때문에 한 명을 찾자마자 `return`하면 안 된다는 점을 확인했다.  
배열을 끝까지 탐색하면서 같은 이름의 회원을 모두 출력하고, 결과가 없을 때만 `found` 변수를 이용해 조회 실패 메시지를 출력해야 했다.

빙고 게임에서는 `board`, `marked`, `called` 배열의 역할을 구분하는 부분이 헷갈렸다.  
숫자를 저장하는 배열, 해당 칸이 체크되었는지 저장하는 배열, 이미 부른 숫자인지 확인하는 배열이 각각 따로 필요하다는 점을 정리했다.

또한 `Random`으로 1부터 `max`까지의 숫자를 만들 때 `rand.nextInt(max) + 1`을 사용해야 하는 이유를 다시 확인했다.  
빙고 줄 수를 계산할 때는 가로, 세로, 대각선을 각각 검사하고, 한 줄이 모두 체크되었는지 `all` 변수를 통해 판단하는 흐름을 연습했다.

`static`과 접근제어자도 다시 정리했다.  
`Start`에서 `BingoGame` 객체를 생성해 `play()`를 호출하는 구조라면 게임 로직 메서드들은 `static`일 필요가 없고,   
외부에서 호출하는 `play()`는 `public`, 내부 보조 메서드는 `private`으로 두는 것이 적절하다는 점을 확인했다.

## 오늘 느낀 점

배열을 단순히 값 여러 개를 저장하는 문법으로만 보면 어렵지 않지만, 실제 과제에 적용하니 구조를 먼저 생각하는 것이 중요하다는 걸 느꼈다.

특히 회원 관리와 빙고 게임 모두 2차원 배열을 사용했지만, 하나는 데이터 목록을 관리하는 구조이고   
다른 하나는 게임판을 표현하는 구조라서 같은 문법도 문제에 따라 다르게 활용된다는 점을 확인했다.

빙고 게임을 개선하면서 고정값을 변수로 바꾸는 것만으로도 코드 전체 구조에 영향을 준다는 점을 알게 되었다.   
앞으로는 처음부터 변경 가능성이 있는 값과 고정해도 되는 값을 구분해서 생각해야겠다고 느꼈다.
