## 오늘 배운 내용

오늘은 제네릭과 예외 처리를 중심으로 실습하고, `HashMap`, `Tree`, `TreeMap` 구현 코드를 통해 컬렉션의 내부 동작을 복습했다.

제네릭의 `T`는 실제 타입을 나중에 지정하기 위한 타입 매개변수다.  
하나의 클래스나 메서드를 여러 타입에서 재사용할 수 있고, 불필요한 형변환을 줄이면서 타입 안정성을 높일 수 있다.

`instanceof`는 객체가 특정 타입인지 확인할 때 사용한다.  
다운캐스팅 전에 실제 객체 타입을 확인하면 `ClassCastException`을 방지할 수 있다.

`intValue()`는 `Integer` 객체의 값을 기본형 `int`로 꺼내고, `Integer.valueOf()`는 `int`나 문자열을 `Integer` 객체로 변환한다.  
`Integer.parseInt()`는 문자열을 기본형 `int`로 변환한다는 차이도 확인했다.

예외 처리에서는 실제 발생한 예외와 `catch`에서 처리하는 예외 타입이 맞아야 한다는 점을 정리했다.  
또한 `try-with-resources`는 `AutoCloseable`을 구현한 자원을 `try (...)` 안에 선언하면   
정상 종료나 예외 발생 여부와 관계없이 자동으로 `close()`를 호출한다.

## 실습 및 과제

> 제네릭과 예외 처리 실습

제네릭의 타입 매개변수와 제한된 타입을 사용해 여러 숫자 타입을 처리하는 흐름을 실습했다.

`T extends Number`로 사용할 수 있는 타입을 제한하고, `instanceof`로 실제 타입을 확인했다.  
이후 `intValue()`나 `doubleValue()`로 기본형 값을 꺼내 연산하고,   
`Integer.valueOf()`나 `Double.valueOf()`로 다시 래퍼 객체를 생성했다.

예외 처리에서는 `try-catch`, `throw`, `throws`의 역할을 확인했다.

`try-with-resources`를 사용하면 기존 방식처럼 `finally`에서 `null`을 확인하고   
직접 `close()`를 호출하지 않아도 되므로 자원 해제 누락을 줄일 수 있었다.

> HashMap, Tree, TreeMap 구현 복습

HashMap에서는 배열의 각 칸을 버킷으로 사용하고,   
해시 충돌이 발생하면 같은 버킷에 노드를 연결 리스트 형태로 이어 붙이는 체이닝 방식을 복습했다.

같은 버킷 인덱스를 가진 키라도 실제 키는 다를 수 있으므로 연결 리스트를 순회하며 `equals()`로 정확한 키를 확인해야 했다.

첫 노드를 삭제할 때는 버킷이 다음 노드를 가리키도록 변경하고,   
중간이나 마지막 노드는 이전 노드의 `next`를 삭제 대상의 다음 노드에 연결해야 했다.

```java
buckets[idx] = cur.next;
prev.next = cur.next;
```

`resize()`로 버킷 배열 크기가 바뀌면 인덱스를 다시 계산해야 한다.  
이때 기존 연결을 잃지 않도록 `cur.next`가 변경되기 전에 다음 노드를 먼저 저장해야 한다.

```java
Node next = cur.next;
```

트리 삽입에서는 빈 자리에 새 노드를 반환하고, 반환된 노드를 부모의 `left`나 `right`에 다시 연결하는 재귀 흐름을 복습했다.

```java
node.left = insertNode(node.left, value);
```

반복 전위 순회에서는 오른쪽 자식을 먼저 Stack에 넣고 왼쪽 자식을 나중에 넣어야 왼쪽부터 방문할 수 있었다.  
반복 중위 순회에서는 왼쪽 끝까지 내려가는 동안 아직 처리하지 않은 부모 노드를 Stack에 저장했다.

> TreeMap 기능 확장

기존 TreeMap 구현에 범위 검색과 인접 키 탐색 기능을 추가했다.

`ceilingKey()`는 주어진 키 이상 중 가장 작은 키를 찾고, `floorKey()`는 주어진 키 이하 중 가장 큰 키를 찾도록 구현했다.  
트리를 탐색하면서 조건을 만족할 가능성이 있는 현재 노드를 후보로 저장하는 방식으로 처리했다.

`headMap(Key)`은 `Key` 미만의 키를 조회하고,   
`subMap(fromKey, toKey)`은 `fromKey` 이상, `toKey` 이하의 키를 조회하도록 구현했다.

범위 안의 키를 정렬된 순서로 출력하기 위해 중위 순회를 활용했다.

> 회원 관리4 구현

회원 관리 프로그램을 인터페이스와 `List<Member>` 기반으로 구현했다.

배열과 별도의 회원 수를 직접 관리하는 대신 `ArrayList`에 회원 객체를 저장했다.  
삭제할 때는 회원 객체 자체를 변경하는 것이 아니라 회원 목록에서 해당 객체를 제거했다.

```java
members.remove(member);
```

플랜별 최대 회원 수는 `PricePlan enum`으로 관리하고, 사용자가 입력한 숫자는 `PricePlan.from()`을 통해 enum 값으로 변환했다.

회원 등급은 `Grade enum`으로 분리했다.
기존 `NormalMember`, `VipMember`에 중복되어 있던 필드와 메서드를 하나의 `GradeMember` 구현체로 합치고,   
등급명과 혜택은 enum 내부에서 관리하도록 구조를 개선했다.

## 헷갈렸던 점

`T extends Number`를 사용하면 `Number`를 상속한 숫자 타입만 받을 수 있다는 점을 알게 되었다.

`T`는 실제로 어떤 숫자 타입이 들어올지 확정되지 않은 상태이므로 `instanceof`로 타입을 확인하고,   
`intValue()`나 `doubleValue()`를 통해 기본형 값을 꺼내야 했다.

`intValue()`, `Integer.valueOf()`, `Integer.parseInt()`의 차이도 다시 정리했다.

* `intValue()` -> `Integer` 객체에서 기본형 `int` 값을 꺼냄
* `Integer.valueOf()` -> `int`나 문자열을 `Integer` 객체로 변환
* `Integer.parseInt()` -> 문자열을 기본형 `int`로 변환

`try-with-resources`는 모든 객체를 사용할 수 있는 것이 아니라   
`AutoCloseable`을 구현한 객체만 사용할 수 있다는 점도 다시 정리했다.

HashMap에서는 버킷의 첫 노드를 삭제하는 경우와 중간 노드를 삭제하는 경우의 연결 변경 방식이 달랐다.  
또한 `resize()` 과정에서 기존 다음 노드를 먼저 저장하지 않으면   
새 버킷 연결을 만드는 과정에서 원래 연결을 잃을 수 있다는 점이 헷갈렸다.

트리 재귀에서는 반환값이 단순한 결과가 아니라 부모 노드의 `left`, `right`   
또는 최초 호출의 `root`에 다시 저장되며 트리 연결을 유지한다는 점을 정리했다.

회원 관리4에서는 배열을 복사하는 `Arrays.copyOf()`와 `ArrayList`의 차이를 다시 확인했다.  
`Arrays.copyOf()`는 더 큰 새 배열을 생성해 기존 값을 복사하지만,   
`ArrayList`는 내부 용량을 자동으로 관리하므로 직접 확장할 필요가 없다.

## 오늘 느낀 점

제네릭과 예외 처리는 문법만 외우기보다 실제 타입과 실행 중 발생하는 상황을 기준으로 이해해야 한다고 느꼈다.

HashMap과 트리 구현을 다시 살펴보면서 컬렉션 메서드를 사용하는 것보다   
내부 연결과 재귀 반환 흐름을 직접 이해하는 과정이 훨씬 중요하다는 점을 확인했다.

회원 관리 프로그램에서는 배열을 컬렉션으로 바꾸고 회원 등급을 enum으로 분리하면서,   
자료구조와 타입을 적절히 선택하면 중복을 줄이고 코드의 역할을 명확하게 만들 수 있다는 점을 느꼈다.
