## 실습 및 과제

> Java 조건문·반복문 실습

Java 기본 문법 실습으로 조건문과 반복문 관련 예제를 작성했다.

조건문 실습에서는 점수에 따라 학점을 출력하는 로직과 메뉴 번호에 따라 다른 결과를 출력하는 로직을 작성했다.  
반복문 실습에서는 사용자 입력을 반복해서 받거나, 특정 조건이 만족될 때까지 프로그램을 계속 실행하는 구조를 연습했다.

특히 자판기 실습에서는 현재 잔액을 기준으로 메뉴를 선택하고, 선택한 음료의 금액을 차감한 뒤, 종료 시 잔돈을 반환하는 흐름을 구현했다.  
이 과정에서 반복을 언제 종료할지와 현재 상태 값을 어떻게 유지할지가 중요하다는 점을 확인했다.

> 컬렉션 기반 가계부 과제

과제로는 컬렉션을 활용한 가계부 프로그램을 구현했다.

날짜별로 지출 항목을 저장하기 위해 `Map<String, List<Item>>` 구조를 사용했고,   
하나의 날짜에 여러 개의 지출 항목을 저장할 수 있도록 구성했다.  
주요 기능으로는 항목 추가, 날짜별 조회, 날짜 전체 삭제, 특정 항목 삭제 기능을 구현했다.

가계부 구현 과정에서는 인터페이스(`AccountBook`)와 구현 클래스(`AccountBookImpl`)를 분리했고, 지출 항목은 `Item` 클래스로 따로 관리했다.  
또한 사용자가 입력한 금액이 숫자가 아닐 경우 `NumberFormatException`을 처리하여 프로그램이 바로 종료되지 않도록 했다.

## 헷갈렸던 점

가계부 과제를 구현하면서 `Map` 안에 `List<Item>`을 값으로 넣는 구조가 헷갈렸다.

날짜를 기준으로 여러 개의 지출 항목을 관리해야 해서 `Map<String, List<Item>>`처럼 중첩된 컬렉션 구조를 사용했다.  
여기에 지출 항목을 `Item` 클래스로 따로 분리해서 관리하다 보니,   
어떤 데이터가 어디에 들어가고 어떤 객체를 꺼내서 사용해야 하는지 구조를 파악하는 데 시간이 걸렸다.

특히 `Map` 안에 `List`가 있고, 그 `List` 안에 다시 `Item` 객체가 들어가는 형태라서 중첩 구조를 머릿속으로 따라가는 것이 헷갈렸다.  
이런 구조는 앞으로 더 많이 사용할 것 같아서 직접 여러 번 작성하면서 익숙해질 필요가 있다고 느꼈다.

`getOrDefault()`는 알고 있는 메서드였지만, 막상 구현할 때 바로 떠올리지 못했다.  
기존 날짜의 지출 목록이 있으면 가져오고, 없으면 새 리스트를 만들어 사용하는 흐름에서 적절히 활용할 수 있었는데,   
컬렉션 구조와 함께 생각하다 보니 바로 적용하지 못했다.

예외 처리도 오랜만에 사용해서 다시 복습이 필요했다.  
사용자가 숫자가 아닌 값을 입력했을 때 `NumberFormatException`이 발생할 수 있고,   
이를 `try-catch`로 처리해야 프로그램이 중간에 종료되지 않는다는 점을 다시 확인했다.

또한 인터페이스와 클래스를 여러 파일로 나누어 구성하는 부분도 아직 익숙하지 않았다.

특히 가계부 과제를 하면서 `Map`, `List`, 클래스 분리, 인터페이스, 예외 처리가 한 번에 사용되었고,  
단순 문법 실습보다 실제 프로그램 구조에 가까워진 느낌이 들었다.
