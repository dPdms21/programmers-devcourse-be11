## 오늘 배운 내용

오늘은 Y:ON의 청년정책·직업훈련 통합 검색 V1을 마무리하고, 코드 리뷰에서 발견된 문제를 개선했다.

직업훈련의 데이터 특성을 고려해 교육 시작일을 기준으로 검색하도록 정리하고, 신청 가능성 필터를 구현했다.   
또한 사용자별 신청 가능성과 저장 여부를 일괄 조회하도록 개선해 N+1 문제를 방지했다.

이후 검색·저장·숨김 API를 문서화하고 PR을 작성했으며, 코드 리뷰에서 발견된 청년정책 마감일 정렬 문제를 수정했다.

마지막으로 추적·알림 기능을 위한 저장 사용자 조회에 키셋 페이지네이션을 적용하고,   
회원 탈퇴 시 저장·숨김 데이터의 외래 키 충돌 문제를 해결했다.

## 실습 및 과제

> 통합 검색 V1 및 신청 가능성 필터 구현

직업훈련은 고용24에서 실제 모집 마감일을 제공하지 않으므로,   
모집 상태를 임의로 변경하지 않고 교육 시작일을 기준으로 개강 예정 공고를 검색하도록 처리했다.

이 과정에서 실제 모집 상태인 `UNKNOWN`과 검색 요청에서 사용하는 `OPEN`의 의미를 구분했다.

이후 신청 가능성 필터를 구현하고, 사용자별 최신 판정 결과를 DB 검색 조건에 결합했다.

검색 과정에서 전체 재판정을 수행하지 않고 저장된 최신 판정 결과만 조회하도록 했으며,   
결과가 없거나 오래된 공고는 신청 가능성 필터에서 제외했다.

신청 가능성 조건을 다른 검색 조건과 함께 DB 쿼리에 적용하고, 정렬과 페이지네이션을 수행해 전체 결과 수와 페이지 정보의 정합성을 유지했다.

> 검색 응답 연동 및 PR 작성

통합 검색 응답에 사용자별 `eligibilityStatus`와 `saved` 정보를 추가했다.

현재 페이지의 공고 ID를 모아 신청 가능성 판정 상태와 저장 여부를 각각 일괄 조회하도록 구성했다.   
이를 통해 공고마다 개별 조회하는 방식에서 발생할 수 있는 N+1 문제를 방지했다.

또한 실제 판정 결과가 `UNKNOWN`인 경우와 판정 결과가 존재하지 않아 `null`인 경우를 구분했다.

검색 및 저장·숨김 API의 Swagger 문서화를 완료하고, 통합 검색과 저장·숨김 기능에 대한 PR을 작성했다.

> 코드 리뷰 반영 및 마감일 정렬 개선

코드 리뷰 과정에서 신청 예정인 청년정책의 마감일이 정렬에 정상적으로 반영되지 않는 문제를 확인했다.

기존 정렬은 신청 시작일이 현재 날짜 이전인 기간만 고려해 `UPCOMING` 정책의 실제 마감일이 정렬 기준에서 제외될 수 있었다.

이를 수정하면서 신청 중인 정책과 신청 예정 정책이 단순 마감일 순서로 섞이는 문제도 함께 검토했다.

최종적으로 `OPEN → UPCOMING → ALWAYS_OPEN → CLOSED → UNKNOWN` 순으로 모집 상태별 우선순위를 적용하고,   
각 상태에 맞는 날짜 정렬 기준을 사용하는 `DEADLINE_PRIORITY`를 구현했다.

직업훈련은 기존 설계대로 교육 시작일이 빠른 순서로 정렬하도록 유지했다.

> 알림 대상 조회 및 키셋 페이지네이션 구현

추적·알림 기능과의 연동을 위해 특정 공고를 저장한 사용자 ID를 조회하는 기능을 추가했다.

초기에는 `Slice` 기반 페이지네이션을 검토했으나,   
알림 대상 조회 도중 사용자가 저장을 해제하면 OFFSET 이동으로 일부 사용자가 누락될 수 있다는 문제를 확인했다.

이를 해결하기 위해 `userId`를 기준으로 마지막 조회 위치 이후의 데이터를 조회하는 키셋 페이지네이션을 적용했다.

또한 조회한 사용자들의 현재 저장 상태를 일괄 재확인할 수 있는 메서드를 구현했다.

저장 상태를 기준으로 알림 대상 사용자를 조회하도록 구현했다.   
다만 숨김을 개인화 추천뿐 아니라 알림에도 적용할지에 대해서는 추가 논의가 필요하다.

> 회원 탈퇴 시 데이터 정합성 개선

회원 탈퇴 기능이 병합된 이후 실제 삭제 흐름을 검토하고, 저장·숨김 데이터와의 외래 키 충돌 문제를 수정했다.

`UserOpportunityPreference.user`에 `ON DELETE CASCADE`를 적용해   
사용자가 삭제되면 연관된 저장·숨김 데이터도 함께 삭제되도록 구성했다.

다만 JPA의 `ddl-auto: update`는 기존 PostgreSQL 외래 키의 삭제 규칙까지 자동으로 변경하지 않는다는 점을 확인했다.

새로운 DB에는 CASCADE 설정이 반영되지만 기존 로컬 DB에는 기존 외래 키가 유지되므로, 별도의 FK 마이그레이션이 필요하다는 점을 정리했다.

또한 Docker로 PostgreSQL을 실행하더라도 DB 데이터와 스키마는 각 환경의 Docker 볼륨에 유지되므로,   
GitHub 코드 변경만으로 기존 DB의 제약 조건이 갱신되지는 않는다는 점을 확인했다.

## 헷갈렸던 점

직업훈련의 실제 모집 상태가 `UNKNOWN`인데 `OPEN` 검색 조건에서는 어떻게 처리해야 하는지 고민했다.

고용24에서 실제 모집 마감일을 제공하지 않으므로 모집 상태를 임의로 변경하지 않고,   
교육 시작일을 기준으로 한 검색 조건과 실제 모집 상태를 구분해야 한다는 점을 정리했다.

청년정책의 마감일 정렬에서는 `UPCOMING` 공고가 정렬 기준에서 누락되는 문제가 발생했다.   
단순 마감일 정렬만으로는 신청 중인 공고와 신청 예정 공고의 우선순위를 보장하기 어려워,   
모집 상태와 날짜 기준을 함께 고려해야 한다는 점을 확인했다.

알림 대상 조회에서는 OFFSET 페이지네이션을 사용해도 되는지 검토했다.   
조회 도중 저장 해제로 데이터가 삭제되면 일부 사용자가 누락될 수 있어, `userId` 기반 키셋 페이지네이션을 적용했다.

또한 `ON DELETE CASCADE`를 적용했는데 기존 PostgreSQL DB의 외래 키가 변경되지 않는 이유를 확인했다.   
JPA의 `ddl-auto: update`는 기존 제약 조건 변경을 보장하지 않으므로 별도의 마이그레이션이 필요하다는 점을 이해했다.

## 오늘 느낀 점

오늘은 통합 검색 V1을 마무리하고, 코드 리뷰를 통해 발견된 문제를 실제 서비스 사용 상황에 맞게 개선했다.

특히 마감일 정렬은 단순히 날짜를 정렬하는 문제가 아니라, 사용자가 어떤 공고를 먼저 확인해야 하는지까지 고려해야 했다.   
기능이 정상적으로 동작하는 것뿐 아니라 데이터의 의미와 사용자 요구사항에 맞는 결과를 제공하는 것이 중요하다고 느꼈다.

또한 알림 대상 조회와 회원 탈퇴 기능을 연동하면서 다른 도메인의 데이터 변경이 예상하지 못한 문제를 발생시킬 수 있다는 점을 확인했다.   
동시 변경 상황과 기존 DB 환경까지 고려해 설계하고 검증하는 과정의 필요성을 느꼈다.

코드 리뷰에서 발견한 문제를 단순히 수정하는 데 그치지 않고, 발생 원인을 확인하고 여러 대안을 비교해 해결 방법을 선택하는 과정이 의미 있었다.
