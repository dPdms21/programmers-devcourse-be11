## 오늘 배운 내용

오늘은 코딩 테스트 특강 4회차 문제를 풀면서 DP의 상태 정의와 점화식 구성 방법, 트리에서 DFS로 값을 부모 방향으로 전달하는 방식을 학습했다.

DP에서는 점화식을 먼저 만들기보다 문제의 목표와 반복되는 선택을 확인하고,   
다음 선택을 위해 필요한 정보만 상태로 정의하는 것이 중요하다는 점을 이해했다.   
순차적인 문제에서는 마지막 선택을 제거했을 때 어떤 이전 상태가 남는지를 생각하면 점화식을 찾는 데 도움이 됐다.

피보나치 수와 2 x n 타일링을 통해 기본적인 1차원 DP를 확인했고, 등굣길에서는 각 칸까지의 경로 수를 상태로 두는 2차원 DP를 연습했다.   
스티커 모으기(2)에서는 원형 배열의 첫 번째와 마지막이 인접하므로 두 경우로 나누어 선형 DP를 적용해야 한다는 점을 확인했다.

완전범죄에서는 상태 정의가 가장 어려웠다.   
`dp[a][b]`의 인덱스 자체를 A와 B의 누적 흔적으로 보고, `boolean` 값에는 해당 상태에 도달할 수 있는지만 저장했다.   
각 물건을 처리할 때 상태가 A·B 선택으로 확장되고, 같은 상태는 합쳐지며 제한을 넘은 상태는 제거되는 흐름을 이해했다.

연속 펄스 부분 수열의 합에서는 펄스 패턴에 Kadane 알고리즘을 적용해 최대 연속 부분합을 구했고,   
현재 위치에서 끝나는 최댓값과 전체 최댓값을 구분해 관리해야 한다는 점을 확인했다.

모두 0으로 만들기에서는 리프부터 가중치를 부모에게 전달하는 트리 후위 처리 구조를 학습했다.   
재귀 DFS에서는 호출 스택이 복귀 순서를 관리하지만,   
반복 DFS에서는 부모 관계와 방문 순서를 직접 저장한 뒤 역순으로 처리해야 같은 흐름을 구현할 수 있다는 점을 이해했다.

## 실습 및 과제

> 피보나치 수

`dp[i] = dp[i-1] + dp[i-2]` 점화식을 이용해 배열에 각 피보나치 값을 저장하는 방식으로 먼저 구현했다.

현재 값을 계산하는 데 실제로 필요한 값은 직전 두 개뿐이므로, 이후에는 이전 두 값만 변수로 유지하는 방식으로 변경했다.  
배열을 사용하지 않아도 작은 문제부터 순서대로 계산하는 동일한 bottom-up DP이며 공간복잡도를 `O(1)`로 줄일 수 있다는 점을 확인했다.

> 등굣길

최단거리를 구하는 것이 아니라 오른쪽과 아래쪽으로만 이동할 때 학교까지 도달하는 경로의 수를 구하는 문제라는 점을 먼저 구분했다.

각 칸까지 도달하는 경로 수를 상태로 두고 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`로 계산했다.

물웅덩이는 별도의 배열에 표시했으며,   
`puddles`의 좌표가 `(x, y)` 순서로 주어지므로 Java 2차원 배열에서는 `[y][x]`로 접근해야 한다는 점을 확인했다.

> 스티커 모으기(2)

짝수 · 홀수 인덱스의 합을 비교하거나 큰 값부터 선택하는 방식으로는 인접한 스티커를 선택할 수 없다는 조건 때문에 최적해를 보장할 수 없었다.

선형 배열에서는 현재 스티커를 선택하지 않는 `dp[i-1]`과 선택하는 `dp[i-2] + sticker[i]` 중 큰 값을 선택한다.

하지만 원형 배열에서는 첫 번째와 마지막도 인접하므로 첫 번째를 선택하는 경우와 선택하지 않는 경우로 나누어 각각 선형 DP를 적용했다.

> 완전범죄

각 물건마다 A가 훔치거나 B가 훔치는 두 선택이 있고, 선택에 따라 두 사람의 누적 흔적이 함께 변하므로 2차원 DP를 사용했다.

`dp[a][b]`를 A의 흔적이 `a`, B의 흔적이 `b`인 상태에 도달할 수 있는지 여부로 정의했다.  
배열의 인덱스 자체가 누적 흔적을 나타내기 때문에 값에는 별도의 최소 비용이 아니라 `boolean`으로 가능 여부만 저장했다.

물건 하나를 처리할 때마다 기존 상태에서 A가 훔치는 경우와 B가 훔치는 경우로 분기하고, 제한을 넘지 않는 상태만 새로운 `next` 배열에 저장했다.  
현재 `dp`를 바로 수정하면 같은 물건을 한 단계에서 다시 사용할 수 있으므로 이전 상태와 다음 상태를 분리해야 한다는 점을 이해했다.

상태가 어떻게 분기되고 같은 상태로 합쳐지는지 코드만으로 이해하기 어려워, 물건별 상태 변화를 단계별로 확인할 수 있는 DP 시각화 자료도 추가했다.

> 2 x n 타일링

완성된 직사각형의 마지막 배치를 기준으로 점화식을 생각했다.

마지막을 세로 타일 하나로 채우면 앞에는 2×(n-1)이 남고, 가로 타일 두 개로 채우면 2×(n-2)가 남으므로 `dp[n] = dp[n-1] + dp[n-2]`로 계산했다.

순차 DP에서는 현재 상태를 만들기 직전의 마지막 선택이 무엇이었는지를 생각하면 이전 상태를 찾기 쉽다는 점을 확인했다.

> 연속 펄스 부분 수열의 합

원래 수열에 인덱스에 따라 `1, -1, 1, -1...` 또는 반대 부호를 적용한 두 펄스 수열에서 최대 연속 부분합을 구했다.

각 위치에서는 현재 값부터 새로 시작하는 경우와 이전 연속합에 현재 값을 이어 붙이는 경우를 비교하는 Kadane 방식을 사용했다.

현재 위치에서 끝나는 최댓값은 이후 다시 작아질 수 있으므로 지금까지의 전체 최댓값을 별도로 유지했으며, 누적합 범위를 고려해 `long`을 사용했다.

> 모두 0으로 만들기

트리를 양방향 인접 리스트로 구성하고, 먼저 전체 가중치 합이 0인지 확인했다.  
연산 전후 전체 합은 변하지 않으므로 처음 합이 0이 아니면 모든 노드를 0으로 만들 수 없다.

합이 0이라면 리프부터 자신의 가중치를 부모에게 전달한다.  
현재 노드를 0으로 만드는 데 필요한 연산 횟수는 가중치의 절댓값만큼이므로 `Math.abs(weight[current])`를 누적하고,   
실제 값은 부호를 유지한 채 부모에게 더했다.

처음에는 재귀 DFS로 자식까지 내려간 뒤 돌아오는 시점에 부모에게 값을 넘기는 구조를 확인했다.  
하지만 트리가 깊으면 Java 호출 스택으로 `StackOverflowError`가 발생할 수 있어,   
실제 구현에서는 반복 DFS로 `parent`와 방문 순서 `order`를 저장한 뒤 역순으로 처리했다.

## 헷갈렸던 점

DP 문제를 볼 때 점화식부터 찾으려고 해서 어떻게 시작해야 하는지가 가장 헷갈렸다.

점화식은 먼저 정하는 것이 아니라, 문제의 목표와 반복되는 선택을 확인한 뒤 다음 선택을 위해 필요한 정보가 무엇인지 상태로 정의하고   
그 상태가 어디에서 오는지를 찾으면서 만들어진다는 점을 정리했다.

특히 “마지막 선택을 제거하면 어떤 작은 문제가 남는가” 또는 “현재 상태가 어떤 이전 상태에서 올 수 있는가”를 생각하면   
순차 DP의 전이를 찾는 데 도움이 됐다.

등굣길에서는 `puddles`가 단순한 좌표 목록이라는 점과 `(x, y)` 좌표를 배열에서는 `[y][x]`로 바꿔 접근해야 한다는 부분이 헷갈렸다.

스티커 모으기(2)에서는 짝수·홀수 위치를 따로 더하거나 가장 큰 값부터 고르면 되지 않는지 고민했다.  
하지만 어떤 값을 선택하면 인접한 값의 선택 가능 여부까지 달라지므로 단순한 규칙으로는 최적해를 보장할 수 없고,   
각 위치까지의 최적값을 DP로 유지해야 한다는 점을 확인했다.

완전범죄가 가장 이해하기 어려웠다.

처음에는 DP 배열이라면 각 칸에 최소 비용이나 정답 값을 저장해야 한다고 생각했지만,   
이 문제에서는 배열의 인덱스 `a`, `b` 자체가 누적 흔적이라는 상태값이었다.  
따라서 배열 값은 해당 상태에 도달할 수 있는지만 나타내면 된다는 점을 시각화를 통해 이해했다.

또한 `next` 배열을 따로 만드는 이유도 처음에는 명확하지 않았다.  
현재 물건을 처리하면서 만들어진 상태를 같은 `dp`에 바로 넣으면 그 상태에서 동일한 물건을 다시 선택하는 문제가 생길 수 있기 때문에,   
한 단계 전 상태와 한 단계 후 상태를 분리해야 한다는 점을 확인했다.

모두 0으로 만들기에서는 양방향 그래프에서 `next == parent[current]`를 건너뛰는 것이 다른 자식으로도 이동하지 못하게 하는 것인지 헷갈렸다.

이는 방금 지나온 부모 방향으로 다시 돌아가는 것만 막는 조건이고, 현재 노드에 연결된 다른 자식으로 내려가는 것은 정상적으로 수행된다.

재귀 DFS와 반복 DFS의 차이도 다시 정리했다.  
재귀에서는 함수 호출이 끝까지 내려갔다가 돌아오는 순서를 자동으로 관리하지만,   
반복문에서는 그 순서를 `order`에 직접 저장하고 반대로 순회해야 리프부터 부모로 처리할 수 있다.

## 오늘 느낀 점

오늘은 DP를 단순히 점화식을 외워 적용하는 유형으로 생각하면 어려운 문제에서 금방 막힌다는 점을 느꼈다.

결국 중요한 것은 문제에서 반복되는 선택을 찾고, 앞으로의 선택을 결정하는 데 필요한 정보만 상태로 남기는 것이다.  
같은 상태로 도달한 여러 경우를 하나로 합치고   
더 이상 가능한 답이 될 수 없는 상태를 제거한다는 관점으로 보니 DP와 완전탐색의 차이도 조금 더 명확해졌다.

특히 완전범죄는 처음에는 `dp[a][b]` 자체가 무엇을 의미하는지 거의 이해하지 못했지만,   
물건별로 상태가 어떻게 분기되고 합쳐지는지를 시각화하면서 2차원 DP를 실제 상태 공간으로 볼 수 있게 된 점이 가장 의미 있었다.

모두 0으로 만들기에서는 재귀 코드가 간단해 보이는 이유가 탐색 순서와 복귀 순서를 호출 스택이 대신 관리해주기 때문이라는 점을 이해했다.  
반복 DFS로 바꾸면 직접 `parent`와 `order`를 관리해야 해 코드가 복잡해지지만,   
깊은 트리에서도 호출 스택 문제를 피할 수 있다는 차이도 기억에 남았다.
