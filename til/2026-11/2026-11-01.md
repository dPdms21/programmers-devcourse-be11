## 오늘 배운 내용

오늘은 Y:ON 프런트엔드 V2 PR의 코드 리뷰를 반영하면서 로고·파비콘 용량을 최적화하고,   
관리자 권한 거부 상태와 추천 숨김 되돌리기 안내의 문제를 개선했다.

관리자 기능에서는 화면 이동과 실제 인증 세션 전환을 구분해 권한 거부 상태를 관리하도록 수정했다.   
추천 숨김 되돌리기에서는 시간제한으로 사용자가 복구 기회를 놓칠 수 있는 접근성 문제를 해결했다.

이후 Chrome 브라우저 테스트의 필수 검증 정책을 보완하여 주요 기능의 회귀 테스트가 CI에서 누락되지 않도록 했다.

마지막으로 최종 팀 프로젝트 발표를 위해 담당 기능과 기술적 성과를 정리하고, 문제 해결 과정과 측정 결과를 중심으로 PPT 초안을 작성했다.

## 실습 및 과제

> 로고·파비콘 용량 최적화

프런트엔드 V2 코드 리뷰를 반영하여 로고와 파비콘의 이미지 용량을 최적화했다.

기존 로고는 1254×1254 해상도에 약 510KB였지만 실제 화면에서는 32~40px 정도로 표시되고 있었다.

이에 로고를 160×160으로 축소하여 약 15KB로 줄였으며, 약 97%의 용량 감소를 확인했다.   
파비콘도 필요한 16·32·48px 이미지만 유지하여 약 68KB에서 6KB로 줄였다.

또한 로고를 `public`에서 `src/assets`로 이동하여 Vite의 해시 파일명과 캐싱 방식을 활용하도록 변경했다.

추가로 256색 압축을 검토했지만 윤곽선에 계단 현상이 발생하여 적용하지 않았다.

> 관리자 권한 거부 상태 및 실행 안내 개선

관리자 페이지에서 권한 거부 상태가 적절하게 유지되는지 검토했다.

초기에는 동일 사용자가 재로그인할 때 접근 거부 상태가 초기화되지 않을 가능성을 확인했지만, 실제 재로그인에서는 문제가 재현되지 않았다.

대신 관리자 API에서 403 응답을 받은 뒤 다른 화면으로 이동했다가 다시 진입하면,   
같은 인증 세션에서도 관리자 API를 다시 호출하는 문제를 발견했다.

원인은 접근 거부 상태가 컴포넌트 내부에 저장되어 화면 이동 시 초기화되는 구조였다.

이에 거부 상태를 React Query 캐시에 저장하고, 실제 로그인·로그아웃에 따른 인증 세션 전환 시에만 초기화하도록 수정했다.

또한 다른 관리자 작업이 진행 중일 때 동시 실행이 제한되는 이유를 화면에 표시하도록 개선했다.

수집 이력 자동 갱신에서는 브라우저 탭이 숨겨지는 것과 창의 포커스가 사라지는 것이 다르며,   
기존 갱신 정책은 탭의 가시성을 기준으로 동작한다는 점을 확인했다.

> 추천 숨김 되돌리기 안내 접근성 개선

기존 추천 공고 숨김 되돌리기 안내는 5초 후 자동으로 사라지는 방식이었다.

하지만 숨김 공고를 별도로 조회하거나 복구하는 화면이 없는 상황에서 사용자가 되돌리기 기회를 놓칠 수 있다는 문제를 확인했다.

특히 스크린 리더 사용자는 안내를 확인하고 버튼으로 이동하는 동안 시간제한이 발생할 수 있었다.

이에 자동 닫힘을 제거하고, 사용자가 `X` 버튼이나 `Escape` 키로 직접 안내를 닫도록 변경했다.

안내를 닫는 동작은 서버의 숨김 상태에 영향을 주지 않으며, 실제 되돌리기 버튼을 눌렀을 때만 숨김 해제 API를 호출하도록 유지했다.

또한 포커스 이동과 계정 전환 시 안내 초기화를 검증했다. 추가 조작이 필요 없는 성공 확인 문구는 기존처럼 일정 시간이 지나면 사라지도록 했다.

이를 통해 화면의 안내를 종료하는 동작과 서버 데이터를 복구하는 동작을 구분하고,   
사용자가 필요한 작업을 완료할 시간을 충분히 제공해야 한다는 점을 확인했다.

> Chrome 브라우저 테스트 필수 검증 등록

기존에는 실제 Chrome을 실행하는 테스트가 존재하더라도 `scripts/test-policy.json`의 `browser` 목록에는 일부만 등록되어 있었다.

해당 정책은 테스트 실행 자체를 결정하는 것이 아니라,   
필수 브라우저 테스트의 존재와 정상 실행 여부를 CI에서 검증하기 위한 설정이라는 점을 확인했다.

이에 관리자 페이지, 추천 숨김 되돌리기, 모든 기기 로그아웃, 사용자 행동 이벤트 관련 테스트를 필수 검증 대상으로 등록했다.

최종적으로 Chrome 브라우저 테스트 11개와 일반 테스트 344개, 총 355개 테스트가 모두 통과했다.

테스트 리포트 정책 검증에서도 위반 사항이 없음을 확인했다.

이 과정에서 Claude Code가 `frontend` 디렉터리만 작업 범위로 인식하여 상위 경로의 공통 설정 파일을 수정하지 못하는 문제도 확인했다.

저장소 루트를 작업 디렉터리로 다시 열어 해결했으며, 여러 모듈의 설정을 함께 변경할 때 작업 범위를 적절하게 지정해야 한다는 점을 이해했다.

> 최종 팀 프로젝트 담당 기능 및 발표 자료 정리

최종 팀 프로젝트 발표를 위해 담당한 통합 검색, 공고 상세 조회, 개인화 추천, 저장·숨김, 사용자 행동 이벤트 및 프런트엔드 구현 내용을 정리했다.

단순한 API와 화면 목록 대신 기능의 목적과 문제 상황, 해결 과정, 검증 결과가 드러나도록 발표 자료를 구성했다.

통합 검색에서는 기존 `LIKE` 방식의 후보 누락과 관련도 정렬 문제를 개선하고, BM25 비교를 통해 규칙 기반 랭킹을 유지한 기술적 선택을 정리했다.

공고 상세 조회에서는 신청 가능성 판정 정보를 조회하는 과정의 중복 SQL을 제거하여   
정책·훈련 상세 조회의 SQL 실행 횟수를 각각 3회 줄인 경험을 핵심 성과로 선정했다.

개인화 추천에서는 사용자 관심 분야와 신청 가능성에 따른 추천 기준, 대량 후보 탐색의 성능 병목과 최적화 과정을 구분해 정리했다.

이를 바탕으로 기술 이름을 나열하기보다 실제 문제를 어떻게 분석하고 해결했는지 전달할 수 있도록 PPT 초안을 작성했다.

## 헷갈렸던 점

로고의 해상도와 용량을 줄이면 표시 품질도 함께 저하되는지 확인했다.   
실제 화면에서 사용하는 크기를 기준으로 최적화하되, 지나친 압축으로 윤곽선이 손상되지 않도록 비교해야 한다는 점을 이해했다.

관리자 권한 거부 상태는 재로그인할 때 초기화되지 않는 것이 문제인지 검토했다.   
실제로는 재로그인이 아니라 동일 세션에서 화면을 이동한 뒤 재진입하는 상황이 문제였으며,   
컴포넌트 상태와 인증 세션 상태를 구분해야 한다는 점을 확인했다.

추천 숨김 되돌리기에서 안내를 자동으로 닫아도 되는지 고민했다.   
사용자의 추가 조작이 필요한 안내에는 충분한 시간을 제공해야 하며, 안내 종료와 실제 숨김 상태 변경을 분리해야 한다는 점을 확인했다.

Chrome 테스트가 실행되고 있는데도 `test-policy.json`에 추가 등록해야 하는 이유를 확인했다.   
테스트 실행 여부와 필수 테스트의 존재·실행 결과를 검증하는 정책은 별개라는 점을 이해했다.

## 오늘 느낀 점

오늘은 코드 리뷰에서 제기된 문제를 수정하면서 예상한 문제가 실제로 재현되는지 먼저 확인하는 과정이 중요하다고 느꼈다.   
특히 관리자 권한 거부 상태는 처음 의심했던 재로그인 문제가 아니라 화면 이동에 따른 상태 초기화가 원인이었다.

이미지 최적화와 추천 숨김 되돌리기 개선에서는 성능과 사용성을 함께 고려해야 한다는 점을 확인했다.   
특히 기존에는 시각장애인과 스크린 리더 사용자의 이용 환경까지 고려하지 못했지만,   
코드 리뷰를 통해 시간제한이 접근성 문제로 이어질 수 있다는 점을 알게 됐다.   
이를 통해 기능을 구현할 때 다양한 사용자의 이용 환경까지 고려해야 한다는 점을 배웠다.

Chrome 테스트 정책을 보완하면서 테스트가 통과했다는 사실뿐 아니라 중요한 검증이 누락되지 않도록 관리하는 것도 필요하다는 점을 이해했다.

최종 발표 자료를 작성하면서는 구현한 기능보다 실제 문제를 발견하고 해결한 경험을 전달하는 것이 중요하다고 느꼈다.   
앞으로도 기술적 선택의 이유와 시행착오, 측정 가능한 결과를 함께 기록해야겠다고 생각했다.
