## 오늘 배운 내용

오늘은 AWS 특강을 통해 소프트웨어의 설계부터 개발, 빌드, 배포, 운영까지 전체 생명주기를 학습했다.

설계 단계에서는 AWS Lambda와 모놀리스, MSA의 특징과 트레이드오프를 비교했다.   
개발·배포 단계에서는 브랜치 기반 협업과 코드 리뷰, CI/CD, Docker, Kubernetes, Terraform 등의 역할을 정리했다.

인프라와 운영에서는 Multi-AZ, IAM 최소 권한, 캐싱, 로그·메트릭·트레이스 기반 관측성의 중요성을 학습했다.   
기술을 단순히 도입하기보다 현재 요구사항에 적합한 이유와 운영 비용을 함께 고려해야 한다는 점을 확인했다.

취업 준비와 관련해서는 주도적으로 문제를 발견하고 해결한 경험을 기록하는 방법과 이력서·포트폴리오·면접 준비 방향에 대한 조언을 들었다.

이후 제5회 알고리즘 코딩테스트에 응시했다.   
비교적 접근하기 수월한 문제도 있었지만, 익숙하지 않은 자료구조 활용과 수학적 개념, 문제 이해 및 시간 배분에서 부족한 부분을 확인했다.

## 실습 및 과제

> AWS 특강 - 서비스 설계 및 개발 방식

AWS Lambda와 모놀리스, MSA의 특징을 비교했다.

Lambda는 요청량이 적거나 불규칙할 때 비용 효율적일 수 있지만, 실행 시간 제한과 DB 커넥션 관리 등을 고려해야 한다.

모놀리스는 애플리케이션 단위로 확장하는 반면, MSA는 필요한 서비스를 독립적으로 확장할 수 있다.   
다만 분산 시스템의 운영 복잡도가 증가하므로   
처음부터 서비스를 분리하기보다 높은 응집도와 낮은 결합도를 갖춘 구조를 설계하는 것이 중요하다는 점을 확인했다.

개발 과정에서는 브랜치 기반 협업과 코드 리뷰의 목적을 정리했다.   
PR에는 변경 내용뿐 아니라 변경 이유와 영향 범위, 테스트 결과를 포함하고, 롤백 가능성까지 고려해야 한다는 점을 배웠다.

또한 환경별 설정을 분리하고 비밀번호와 API Key 같은 민감정보는 코드 외부에서 관리해야 한다는 점을 확인했다.

> CI/CD 및 클라우드 인프라 운영

빌드와 배포 과정에서 Docker, Kubernetes, Argo CD, Terraform의 역할을 학습했다.

Kubernetes는 Desired State를 기준으로 실제 애플리케이션 상태를 조정하며, Argo CD는 GitOps 기반 배포를 지원한다.

AWS ECR은 컨테이너 이미지를 저장하는 서비스이고 ECS는 컨테이너를 실행하고 관리하는 서비스라는 차이도 확인했다.

Kubernetes 실습에서는 `kubectl`로 Pod를 생성하고 상태와 로그를 확인하는 기본 명령어를 학습했다.

운영 단계에서는 Multi-AZ를 통한 고가용성 확보, IAM 최소 권한 원칙, Redis·Valkey 캐싱, 로그·메트릭·트레이스 기반 관측성을 정리했다.

이를 통해 배포 이후에도 장애를 감지하고 원인을 분석할 수 있는 환경을 구성해야 한다는 점을 이해했다.

> 보안 및 개발자 성장·취업 준비 특강

토스 페이스페이의 보안성과 실제 사용에 관해 질문했다.

강사님은 해당 서비스의 구체적인 내부 구현은 알기 어렵다고 답변했지만, 지속적인 보안 투자가 장기적으로 기업의 경쟁력이 될 수 있다고 설명했다.

이를 통해 보안은 사고를 예방하기 위한 비용뿐 아니라 사용자 신뢰를 확보하기 위한 투자라는 관점을 배웠다.

취업과 관련해서는 신입 개발자의 주도성과 문제 해결 경험의 중요성을 강조했다.

이력서는 자신의 경험을 충분히 정리한 원본을 바탕으로 채용 공고에 맞게 수정하고,   
포트폴리오는 문제 상황과 해결 과정, 기술적 선택 및 측정 결과를 중심으로 구성해야 한다는 점을 확인했다.

면접에서는 STAR 기법을 활용하고 GC, TCP, 브라우저 요청 처리 과정 등의 기본기를 준비해야 한다는 조언을 들었다.

자격증은 서류 전형에서 도움이 될 수 있지만, 실제 면접에서는 기술적 전문성과 문제 해결 역량이 더 중요하다는 점도 들었다.

기술적 배경지식을 쌓는 방법에 대해서는 개념 학습 후 직접 예제를 실행하고 시행착오를 기록하는 방식이 효과적이라는 조언을 들었다.

> 제5회 알고리즘 코딩테스트

제5회 알고리즘 코딩테스트에 응시했다.

1·2번은 비교적 접근하기 수월했지만, 자료구조를 활용하는 방식에서 평소의 풀이 습관을 돌아보게 됐다.

`Map`을 사용하면 해결할 수 있다는 점을 알고 있어도 익숙하지 않아 직접 구현하는 방식을 선택하려는 경향이 있었다.

3번은 필요한 수학적 개념이 바로 떠오르지 않았고 문제 자체를 이해하는 데도 시간이 걸렸다.   
구현에 시간이 많이 필요할 것으로 판단해 제한 시간 내에 해결하지 못했다.

4번은 난도가 있었지만 문제를 충분히 분석하고 접근 방식을 정리하는 것이 중요하다고 느꼈다.

전체적으로 문제 풀이 속도가 빠른 편은 아니므로,   
익숙한 구현 방식만 고집하지 않고 적절한 자료구조를 선택하는 연습과 시간 배분이 필요하다는 점을 확인했다.

## 헷갈렸던 점

Lambda와 MSA가 항상 모놀리스보다 효율적인 구조인지 궁금했다.   
요청량과 서비스 규모, 확장 요구사항에 따라 적합한 구조가 달라지며,   
독립적인 확장이라는 장점과 운영 복잡도 사이의 트레이드오프를 고려해야 한다는 점을 이해했다.

ECR과 ECS의 역할도 다시 구분했다.   
ECR은 이미지를 저장하고 ECS는 컨테이너의 실행과 관리를 담당하므로, 이미지 저장과 서비스 운영은 서로 다른 역할이라는 점을 확인했다.

알고리즘 코딩테스트에서는 `Map`을 사용하면 되는 상황에서도 직접 구현하는 방식이 더 익숙해 굳이 자료구조를 사용해야 하는지 고민했다.   
단순히 구현할 수 있는지가 아니라 코드의 복잡도와 효율성, 문제에 적합한 자료구조를 함께 판단하는 연습이 필요하다는 점을 느꼈다.

## 오늘 느낀 점

오늘 AWS 특강을 통해 기술을 많이 알고 사용하는 것보다 현재 문제에 적합한 기술을 선택하고   
그 이유를 설명할 수 있는 능력이 중요하다는 점을 다시 확인했다.   
특히 확장성과 운영 복잡도, 비용을 함께 고려하는 관점이 필요하다고 느꼈다.

취업 관련 조언을 들으면서 Y:ON 프로젝트에서 진행한 통합 검색 성능 개선, 상세 조회 SQL 최적화, 개인화 추천 병목 분석 역시   
중요한 문제 해결 경험이라는 점을 확인했다.  
앞으로는 구현한 기능보다 문제를 발견하고 원인을 분석한 과정, 기술적 선택과 결과를 명확하게 설명할 수 있도록 정리해야겠다고 생각했다.

알고리즘 코딩테스트에서는 알고 있는 자료구조도 익숙하지 않으면 실제 풀이에서 활용하지 않게 된다는 점을 느꼈다.   
또한 문제 이해와 접근 방식 결정에 시간이 걸려 풀이를 완성하지 못한 경험을 통해,   
다양한 문제에 익숙해지는 것뿐 아니라 제한 시간 안에 적절한 방법을 선택하는 연습도 필요하다고 생각했다.
