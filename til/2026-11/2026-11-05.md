## 오늘 배운 내용

두 프로젝트 모두 문제 정의 → 해결 방식 설계 → 실행 → 피드백의 4단계를 기준으로 기술적 경험을 재구성하고,   
문제 해결 과정과 성과가 효과적으로 전달되도록 시각화 자료를 보완했다.

또한 각 경험이 자연스럽게 연결되도록 내용의 순서와 배치를 조정하고, 전체적인 흐름과 형식을 통일했다.   
이를 통해 Y:ON 상세 포트폴리오를 완성했으며, Gudit은 기존 내용을 중심으로 구성을 개선했다.

## 실습 및 과제

> Y:ON 상세 포트폴리오 수정 및 완성

Y:ON의 검색·상세 조회·개인화 추천·행동 이벤트 관련 문제 해결 경험을 4단계 구조에 맞춰 정리했다.

문제 상황부터 해결 방법의 검토와 적용, 결과 검증까지 자연스럽게 이어지도록 내용을 구성하고,   
기술적 분석과 성능 개선 결과를 이해하기 쉽도록 시각화 자료를 보완했다.

또한 대표 경험의 배치와 문서 형식을 통일하여 Y:ON 상세 포트폴리오를 완성했다.

> Gudit 상세 포트폴리오 구성 개선

Gudit에도 동일한 4단계 구조와 시각화 기준을 적용하여 기존 포트폴리오를 수정했다.

특히 별도로 정리되어 있던 기술 선택 이유를 각 문제의 해결 과정에 배치하여, 문제 상황과 대안 검토, 최종 선택의 근거가 자연스럽게 이어지도록 구성했다.

또한 문제 해결 과정과 측정 결과를 효과적으로 전달할 수 있도록 시각화와 문서 구성을 보완하고, Y:ON과 전체적인 형식이 일관되도록 정리했다.

## 헷갈렸던 점

기술적 문제 해결 경험을 4단계 구조에 맞춰 정리하면서 기존 내용을 어떤 순서로 배치해야 자연스럽게 연결될지 고민했다.   
모든 경험을 동일한 형식에 맞추되, 프로젝트마다 문제 발생 과정과 해결 흐름의 차이는 유지하는 것이 중요하다는 점을 확인했다.

## 오늘 느낀 점

오늘은 전날 특강과 컨설팅에서 배운 내용을 Y:ON과 Gudit 포트폴리오에 직접 적용했다.   
특히 문제 해결 과정을 4단계로 정리하고 시각화 자료를 보완하면서, 기술적 경험을 어떻게 보여주는지도 중요하다는 점을 느꼈다.

또한 전체 흐름과 형식을 맞추는 과정에서 각 문제 해결 경험의 연결성이 더 명확하게 드러날 수 있다는 점을 확인했다.   
Y:ON 상세 포트폴리오를 완성하고 Gudit도 개선한 만큼, 앞으로 나머지 프로젝트에도 같은 기준을 적용하고 싶다.
