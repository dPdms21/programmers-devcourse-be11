# 도커란?

도커는 컨테이너를 만들고 실행하고 배포하는 도구다.

도커는 새로운 격리 기술을 만든 것이 아니다.  
리눅스가 이미 가지고 있던 기능(`namespace`, `cgroup`)을 사용하기 쉽게 제공하고,   
실행 환경을 이미지로 패키징하여 이동하고 배포할 수 있게 만든 것이다.

## 1. 도커가 제공하는 세 가지
- 이미지: 실행 환경을 담은 패키지 - 배포의 단위
- 컨테이너: 이미지를 실행한 상태 - 실행의 단위
- 레지스트리: 이미지를 저장하고 주고받는 저장소 - 유통의 경로

- **도커 허브**: Docker사가 운영하는 이미지 레지스트리다.

## 2. 이미지와 컨테이너

- **이미지는 읽기 전용이다.** 한번 만들어지면 내용이 바뀌지 않는다.
- **컨테이너는 그 이미지를 실행한 것이다.** 하나의 이미지로 컨테이너를 여러 개 만들 수 있고, 각 컨테이너는 서로 독립적으로 동작한다.

### 이미지에 들어 있는 것
- 애플리케이션 실행 파일
- 실행에 필요한 런타임
- 운영체제의 파일 시스템 일부 (라이브러리와 기본 명령어들)
- 시작 방법 - 어떤 명령으로 실행할 것인지에 대한 정보

### 들어 있지 않은 것

**커널이다.** 커널은 이미지에 포함되지 않고 호스트의 것을 그대로 사용한다.

## 3. 이미지는 파일 시스템이다.

이미지는 파일 시스템 계층과 실행에 필요한 메타데이터로 구성된다.   
파일 시스템에는 `/usr`, `/lib`, `/opt`, `/app` 등의 디렉터리와 파일이 포함될 수 있다.

실행에 필요한 파일들이 디렉터리 구조로 담겨 있고, 컨테이너의 프로세스는 **이 트리를 최상위 경로로 보고** 동작한다.

## 4. 이미지는 계층으로 쌓인다.

기반 이미지 위에 변경된 내용을 층으로 얹어 만든다.  
만드는 과정에서 발생한 **파일 시스템의 변경분이 계층 하나**가 된다.

```dockerfile
# 기반 이미지 지정(여러 계층으로 구성될 수 있음)
FROM eclipse-temurin:25-jre

# 작업 디렉터리 설정(없으면 생성)
WORKDIR /app

# 애플리케이션 파일을 복사하여 파일 시스템 계층 추가
COPY app.jar /app/app.jar
```

계층은 디렉터리 단위가 아니다.  
이미지의 파일 시스템 계층은 `RUN`, `COPY` 등 파일 시스템을 변경하는 명령을 통해 생성된다.   
`WORKDIR`처럼 설정을 변경하는 명령은 이미지 메타데이터에도 영향을 주며, 파일 시스템 계층과 Dockerfile 명령이 항상 일대일로 대응하는 것은 아니다.  
`COPY`로 생성된 계층에는 추가된 `app.jar`가 포함되며, 기반 이미지의 `/usr`, `/lib` 등을 다시 복사하지 않는다.

여기서 두 가지 이점이 나온다.
- **공유**: 같은 계층은 여러 이미지가 공유한다. 이미지가 여러 개여도 디스크 사용량은 단순 합계보다 작다.
- **증분 전송**: 애플리케이션 파일만 변경되고 이전 계층의 캐시가 유효하다면, 변경된 계층부터 다시 빌드할 수 있다. 레지스트리에도 이미 존재하는 계층은 재사용할 수 있으므로 변경된 계층을 중심으로 전송할 수 있다.

### 자바 베이스 이미지는 어느 것을 쓰나

```
eclipse-temurin    Eclipse Adoptium 프로젝트의 OpenJDK 배포판
amazoncorretto     AWS가 제공하는 OpenJDK 배포판
bellsoft/liberica  BellSoft가 제공하는 OpenJDK 배포판
azul/zulu-openjdk  Azul이 제공하는 OpenJDK 배포판
openjdk            기존 Docker Official Image는 지원 종료 상태
                   (일부 Early Access 태그 제외)
```

temurin을 기본으로 두는 이유
- 기존 `openjdk` 공식 이미지의 지원 종료 이후 사용할 수 있는 대체 배포판 중 하나다.
- JDK 버전과 운영체제에 따른 이미지 태그를 제공하므로 실행 환경에 맞게 선택할 수 있다.
- 특정 클라우드 제공업체에 종속되지 않고 사용할 수 있다.
