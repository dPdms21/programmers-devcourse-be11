# AWS 인프라를 위한 네트워크 기초

## 1. IP 주소

### 1-1. 생김새

IPv4 주소는 32비트이다.  
8비트씩 4덩어리로 나누고, 점으로 구분한다.

```
192.168.10.25
```

- 한 덩어리를 옥텟이라 부른다.
- 옥텟 하나는 0 ~ 255
- 전체 개수는 2^32 = 약 43억 개

#### 옥텟을 2진수로 보기

10진수 172는 아래와 같이 표기할 수 있다.
```
자릿값  100  10  1
       1    7   2  ->  1 * 100 + 7 * 10 + 2 * 1 => 172
```

2진수
- 자릿값이 10배씩이 아닌 **2배씩** 커진다.
- 각 칸에는 **0 또는 1만** 들어간다.

```
128  64  32  16  8  4  2  1
 1    0   1   0  1  1  0  0

 -> 128 + 32 + 8 + 4 = 172
```

그래서 172 = 10101100 이다.

#### 자주 나오는 값

```
10  = 0 0 0 0 1 0 1 0 = 2 + 8
172 = 1 0 1 0 1 1 0 0 = 128 + 32 + 8 + 4
192 = 1 1 0 0 0 0 0 0 = 128 + 64
255 = 1 1 1 1 1 1 1 1 = 전부
0   = 0 0 0 0 0 0 0 0 = 없음
```
- 옥텟은 8비트가 전부 1이면 255이기 때문에 범위가 0 ~ 255이다.

### 1-2. 주소는 두 부분으로 나뉜다.
- 네트워크부 / 호스트부
- 네트워크부: 어느 동네인지
- 호스트부: 그 동네의 몇 번지인지

```
192.168.10.25
네트워크부 / 호스트부
```

### 1-3. 서브넷 마스크 - 경계를 알려주는 숫자

주소만 보면 어디까지가 동네인지 알 수 없다.  
그래서 "앞에서 몇 비트까지가 동네(네트워크부)다" 라는 정보를 따로 준다.  
바로 **서브넷 마스크**다.

#### 마스크는 1과 0으로 경계를 표시한다.

IP를 2진수로 풀면 32비트이다.  
마스크도 똑같이 32비트인데, 네트워크부 자리는 1, 호스트부는 0으로 채운다.

```
주소  : 192.168.10.25 = 11000000.10101000.00001010.00011001
마스크: 255.255.255.0 = 11111111.11111111.11111111.00000000
-> 1로 된 부분이 네트워크부이고, 0이 호스트부이다.
```

그래서 앞 24비트(192.168.10)가 이 동네를 뜻하고, 25가 번지를 뜻한다.

#### 같은 주소, 다른 마스크

```
주소  : 192.168.10.25 = 11000000.10101000.00001010.00011001
마스크: 255.255.0.0   = 11111111.11111111.00000000.00000000

→ 앞 16비트가 네트워크부이고, 뒤 16비트가 호스트부이다.
```

주소는 같은데 마스크가 다르면 동네의 크기가 달라진다.  
**IP 주소는 항상 마스크와 세트로 다녀야 의미가 완성된다.**

#### 마스크를 짧게 표기하는 CIDR

CIDR = Classless Inter-Domain Routing. "사이더"라고 읽는다.

- Classless - 네트워크부 길이를 8/16/24 로 고정하지 않고 아무 숫자나 쓴다.
- Inter-Domain Routing - 원래는 네트워크 사이의 라우팅 규칙 이름. 거기서 쓰는 /24 표기 자체를 CIDR라고 부른다.

마스크에서 1의 개수를 세서 / 뒤에 쓴다.
```
255.255.255.0 -> 1이 24개 -> /24
255.255.0.0   -> 1이 16개 -> /16
255.0.0.0     -> 1이 8개  -> /8
```

```
192.168.10.25/24
192.168.10.25 + 255.255.255.0
```
둘은 완전히 같은 의미다. 요즘은 /24쪽으로 주로 사용한다.

### 1-4. CIDR로 네트워크 크기 읽기

네트워크부 길이를 / 뒤 숫자로 쓴다.

```
10.0.0.0/16 네트워크부 16비트
10.0.1.0/24 네트워크부 24비트
10.0.1.0/28 네트워크부 28비트
```

주소 개수 계산. 32에서 고정된 비트를 빼면 호스트부 비트가 남는다.

```
개수 = 2 ^ (32 - n)
/16 => 호스트부 16비트 => 2^16 = 65,536
/24 => 호스트부 8비트 => 2^8 = 256
/28 => 호스트부 4비트 => 2^4 = 16
```

**뒤 숫자는 고정된 부분의 길이다. 고정이 길수록 남는 자리가 적다 = 네트워크 크기가 작아진다**

#### 장비에 줄 수 없는 주소 2개

호스트부가 전부 0인 것과 전부 1인 것은 예약돼 있다.

```
10.0.1.0/24 에서

10.0.1.0 호스트부 00000000 네트워크 주소 -> "이 동네 전체"를 가리키는 이름표
10.0.1.255 호스트부 11111111 브로드캐스트 -> "이 동네 전원에게" 보내는 주소
10.0.1.1 ~ 254 실제 장비에 줄 수 있는 주소 범위
```

- .0 : 아파트 단지 이름
- .255 : 전 세대 안내방송

둘 다 특정 집이 아니다. 그래서 /24 는 256개지만 장비는 254대까지다.

### 1-5. 사설 IP와 공인 IP

인터넷 = 전 세계 라우터가 서로 연결된 망이다.  
그 망에서 통하는 주소가 **공인 IP**고, 인터넷 라우터는 공인 IP의 경로만 알고 있다.

인터넷 라우터에 등록하지 않기로 약속한 대역이 셋 있다.

```
10.0.0.0     ~ 10.255.255.255     10.0.0.0/8
172.16.0.0   ~ 172.31.255.255     172.16.0.0/12
192.168.0.0  ~ 192.168.255.255    192.168.0.0/16
```

- 이 대역은 **사설 IP**이다.
- 인터넷 라우터는 이 주소의 경로를 모른다. 패킷이 오면 버린다. 밖으로 못 나간다.
- 그래서 회사마다, 집마다 같은 주소를 겹쳐 써도 된다. 어차피 밖으로 안 나간다.
- 공인 IP는 인터넷에서 전역적으로 라우팅할 수 있도록 할당되는 주소다.
- 사설 IP 대역 밖이라고 해서 모두 공인 IP는 아니며, 실제 접근 가능 여부는 라우팅과 방화벽 설정에 따라 달라진다.

우리가 본 것
- 집 공유기 -> 192.168.x.x
- docker-compose 컨테이너 -> 172.18.x.x 같은 주소
- AWS VPC -> 10.x.x.x 를 가장 많이 쓴다.

전부 사설 IP다. 

사설 IP 장비가 인터넷에 나가려면 누군가 공인 IP로 바꿔줘야 한다.  
그 역할이 **NAT**이다. 집 공유기가 하는 일이고, AWS에서는 NAT Gateway가 한다.

NAT = Network Address Translation. 네트워크 주소 변환.

```
나갈 때 10.0.11.25 -> NAT -> 3.x.x.x (NAT의 공인 IP)로 바꿔서 내보냄
들어올 때 3.x.x.x -> NAT -> 10.0.11.25로 되돌려서 전달
```

- NAT는 주소와 포트의 변환 정보를 테이블에 기록하고, 응답을 원래 장비에 전달한다.
- 그래서 사설 IP 장비 여러 대가 공인 IP 하나를 나눠 쓴다.
- 밖에서 먼저 들어오는 건 표에 없어서 버려진다. -> "나가기만 되는 문"

## 2. VPC

### 2-1. 정의

VPC = Virtual Private Cloud

AWS 안에 논리적으로 격리된 **나만의 네트워크**다.  
회사 사무실에서 깔린 사내망을 클라우드에 옮긴 것이라고 보면 된다.

### 2-2. 만들 때 정하는 것

VPC를 생성할 때 기본 IPv4 CIDR 블록을 지정한다.  
CIDR은 VPC가 사용할 IP 주소 범위를 나타내며, 생성 후 필요에 따라 추가 CIDR 블록을 연결할 수 있다.

```
10.0.0.0/16
```

CIDR은 특정 전용이 아니다. IP 범위를 적어야 하는 곳이면 어디든 쓴다.
```
VPC          10.0.0.0/16       전체 범위
서브넷        10.0.1.0/24       그 안의 조각
라우트 대상    0.0.0.0/0         모든 주소
SG 소스       0.0.0.0/0         어디서든
SG 소스       203.0.113.5/32    이 IP 하나만 (예시 IP)
```

* 향후 필요한 IP 주소 규모를 고려하여 CIDR을 정한다.
* VPC 생성 시 IPv4 CIDR 블록의 허용 범위는 /16 ~ /28이다.
* 일반적으로 사설 IP 대역에서 선택한다.

### 2-3. 성질

- VPC는 **리전**단위다. 서울 리전에서 만들면 서울 리전 전체에 걸친다.
- VPC끼리는 기본적으로 완전히 격리된다.
- VPC의 인스턴스는 기본적으로 프라이빗 IPv4 주소를 사용하며, 필요에 따라 퍼블릭 IPv4 주소를 추가로 할당받을 수 있다.
- 그래서 인터넷 연결은 **따로 붙여야**한다. 기본적으로 안 된다.

## 3. Subnet

### 3-1. 정의

VPC의 CIDR을 잘라 만든 조각이다.

```
VPC       10.0.0.0/16  65,536개
├─ 서브넷  10.0.1.0/24     256개
└─ 서브넷  10.0.11.0/24    256개
```

- 서브넷 CIDR은 VPC CIDR 안에 있어야 한다.
- 서브넷끼리 겹치면 안 된다.

"안에 있어야 한다."의 뜻  
VPC 10.0.0.0/16 = 10.0.0.0 ~ 10.0.255.255 일 때

```
10.0.1.0/24     10.0.1.0 ~ 10.0.1.255       O   범위 안, 더 작음
10.0.0.0/16     10.0.0.0 ~ 10.0.255.255     O   VPC 와 같음. 서브넷 하나가 전부 차지
10.0.0.0/15     10.0.0.0 ~ 10.1.255.255     X   VPC 보다 큼
10.1.0.0/24     10.1.0.0 ~ 10.1.0.255       X   범위 밖 (10.1 은 10.0 이 아니다)
```

- 서브넷의 / 숫자는 VPC 와 같거나 커야 한다.
- 서브넷의 주소 범위는 VPC 범위 안이어야 한다.

### 3-2. 서브넷은 AZ 하나에 속한다.

```
리전 = 서울
AZ = 리전 내에서 독립적인 전력·네트워크 등을 갖춘 하나 이상의 데이터센터로 구성된 가용 영역
```

- VPC는 리전 단위
- 서브넷은 AZ 단위

왜 AZ를 나누나  
-> AZ 하나가 죽어도 다른 AZ는 산다.

### 3-3. AWS가 예약하는 주소 5개

서브넷마다 5개는 못 쓴다.
```
10.0.1.0 - 네트워크 주소
10.0.1.1 - VPC 라우터
10.0.1.2 - AWS 예약 주소
10.0.1.3 - 향후 사용을 위해 예약
10.0.1.255 - 브로드캐스트
```
서브넷 /24 기준 251개 (256 -5) 사용 가능.  
VPC가 10.0.0.0/16이면 DNS 서버 주소는 10.0.0.2이다.  
10.0.1.2는 서브넷에서 AWS가 예약한 주소로, DNS 서버 주소와는 다르다.

## 4. Public/Private

### 4-1. 무엇이 Public을 결정하나

서브넷에 Public이라는 속성은 없다.  
결정하는 것은 **라우트 테이블**이다.

라우트 테이블 = 이 서브넷에서 나가는 패킷을 어디로 보낼지 적은 표

```
10.0.0.0/16 local (VPC 안은 그냥 간다)
0.0.0.0/0    ???  (그 외 전부 = 인터넷)
```

- 0.0.0.0/0 이 어디로 가느냐가 Public/Private을 가른다.

### 4-2. Internet Gateway

IGW = VPC와 인터넷 사이의 문. 양방향이다.

- VPC당 하나.
- 들어오는 것도 되고 나가는 것도 된다.

```
0.0.0.0/0 -> IGW
```

이 줄이 있으면 **Public 서브넷**이다.

### 4-3. NAT Gateway

NAT GW = 나가기만 되는 문.

- 안에서 밖으로는 된다. (패키지 설치, 외부 API 호출)
- 밖에서 안으로는 안 된다.
- 인터넷 연결용 Public NAT Gateway는 Public 서브넷에 배치한다. IGW를 거쳐 인터넷으로 나가야 하기 때문이다.

```
0.0.0.0/0 -> NAT GW
```

이 줄이 있으면 **Private 서브넷** 이다.

밖에서 못 들어오는 이유
- private 장비는 공인 IP가 없다. 사설 IP로는 인터넷에서 패킷을 보낼 수조차 없다.
- NAT 는 안에서 시작한 연결만 표에 기록한다.

**Public 서브넷**

* 라우트 테이블에 Internet Gateway로 향하는 경로가 있다.
* 인스턴스가 인터넷과 IPv4 통신하려면 공인 IP도 필요하다.
* 실제 접근 여부는 Security Group과 NACL 등의 설정에 따라 달라진다.

**Private 서브넷**

* Internet Gateway로 향하는 직접 경로가 없다.
* NAT Gateway를 통해 인터넷으로 나갈 수 있다.
* 인터넷에서 시작한 연결은 NAT Gateway를 통해 직접 받을 수 없다.

집 공유기와 같다. 노트북은 인터넷에 잘 나가지만, 밖에서 노트북에 먼저 접속할 방법은 없다.

### 4-4. 방화벽 두 종류

Security Group
- 인스턴스 단위
- 허용 규칙만 쓴다.
- 들어온 요청의 응답은 자동으로 나간다.

NACL
- 서브넷 단위
- 허용과 거부 둘 다
- 응답 트래픽도 규칙에 있어야 한다.
- 기본값이 전부 허용이라 보통 안 건드린다.
