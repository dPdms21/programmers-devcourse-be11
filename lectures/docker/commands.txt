*** Gradle ***

빌드 결과물 삭제
.\gradlew.bat clean

실행 가능한 JAR 생성 (테스트 제외)
.\gradlew.bat bootJar -x test

JAR 실행 (실제 생성된 파일명 사용)
java -jar build/libs/config-service-0.0.1-SNAPSHOT.jar

빌드 후 바로 실행
.\gradlew.bat bootRun

Gradle Daemon 상태 확인
.\gradlew.bat --status

Gradle Daemon 종료
.\gradlew.bat --stop

*** Docker ***

=> config-service
이미지 생성
docker build -t config-service:latest .

컨테이너 실행
컨테이너는 기본적으로 호스트의 임의 파일에 접근할 수 없다.
-v 옵션으로 호스트 폴더를 컨테이너 내부 경로에 마운트한다.
:ro는 컨테이너에서 읽기 전용으로 접근한다.

docker run -d --name config-service -p 8888:8888 `
  -v "D:\dev\programmers-devcourse-be11\practice\msa\config-repo:/config-repo:ro" `
  -e CONFIG_REPO_PATH=file:/config-repo `
  config-service:latest

=> auth-service
docker build -t auth-service:latest .

docker run -d --name auth-service -p 8082:8082 `
  --env-file ..\.env `
  -e CONFIG_SERVICE_URL="http://host.docker.internal:8888" `
  -e AUTH_DB_URL="jdbc:mysql://host.docker.internal:3306/board_auth?useSSL=false&serverTimezone=UTC&characterEncoding=UTF-8&allowPublicKeyRetrieval=true" `
  -e BOARD_SERVICE_URL="http://host.docker.internal:8081" `
  auth-service:latest

=> board-service
docker build -t board-service:latest .

docker run -d --name board-service -p 8081:8081 `
  --env-file ..\.env `
  -e CONFIG_SERVICE_URL="http://host.docker.internal:8888" `
  -e BOARD_DB_URL="jdbc:mysql://host.docker.internal:3306/board_app?useSSL=false&serverTimezone=UTC&characterEncoding=UTF-8&allowPublicKeyRetrieval=true" `
  -e AUTH_SERVICE_URL="http://host.docker.internal:8082" `
  board-service:latest

=> edge-service
docker build -t edge-service:latest .

docker run -d --name edge-service -p 8000:8000 `
  -e AUTH_SERVICE_URL="http://host.docker.internal:8082" `
  -e BOARD_SERVICE_URL="http://host.docker.internal:8081" `
  edge-service:latest

=> web-service
docker build -t web-service:latest .

docker run -d --name web-service -p 8080:8080 `
  -e EDGE_SERVICE_URL="http://host.docker.internal:8000" `
  web-service:latest

컨테이너 확인
- 실행 중: docker ps
- 전체 상태: docker ps -a

로그 확인 (실시간)
docker logs -f config-service

사용하지 않는 이미지·컨테이너·네트워크 등 정리 (다른 프로젝트 리소스도 삭제 대상이 될 수 있으므로 주의)
docker system prune -a

멈추기
docker stop [컨테이너ID]

*** Docker Compose ***

기동 (data → service → front)

-f (= file): 사용할 Compose 파일 지정
-d (= detach): 백그라운드 실행

1. 데이터 (msa-network 생성 + MySQL)
   docker compose -f docker-compose.data.yml up -d

2. 서비스 (Config → Auth/Board/Edge)
   docker compose -f docker-compose.service.yml up -d --build

3. 프론트 (Web)
   docker compose -f docker-compose.front.yml up -d --build

--build는 컨테이너를 시작하기 전에 이미지를 빌드하도록 지정한다.
코드 수정 후 up -d --build를 실행하면 이미지를 빌드하고 필요한 컨테이너를 재생성한다.
restart만으로는 변경된 코드가 반영되지 않는다.

종료 (역순: front → service → data)
docker compose -f docker-compose.front.yml down
docker compose -f docker-compose.service.yml down
docker compose -f docker-compose.data.yml down

완전 초기화 (Compose 컨테이너 및 관리 볼륨 삭제)

# data 프로젝트의 MySQL 데이터 볼륨과
# service 프로젝트의 board-uploads 볼륨까지 삭제되므로 주의

docker compose -f docker-compose.front.yml down -v
docker compose -f docker-compose.service.yml down -v
docker compose -f docker-compose.data.yml down -v

상태 확인
docker ps
docker ps -a
docker compose -f docker-compose.service.yml ps

로그 확인
docker logs -f auth-service
docker compose -f docker-compose.service.yml logs -f

개별 서비스 재시작
docker compose -f docker-compose.service.yml restart auth-service

코드 수정 후 특정 서비스 재빌드 및 재생성
docker compose -f docker-compose.service.yml up -d --build auth-service

*** 쉘 스크립트 실행 권한 (Git Bash / WSL) ***
chmod +x start.sh
chmod +x stop.sh

*** 쉘 스크립트 실행 ***
./start.sh
./stop.sh        # 컨테이너만 종료, 볼륨 유지
./stop.sh -v     # 컨테이너 종료 + 관리 볼륨 삭제
