# 트리

## 트리 구조

트리는 하나의 루트에서 시작해 여러 자식 노드로 계층이 확장되는 비선형 자료구조다.

각 노드는 부모와 자식 관계를 가지며, 하나의 노드 아래에 여러 하위 노드가 연결될 수 있다.

```text
Root
├─ Child
│  ├─ Leaf
│  └─ Leaf
└─ Child
```

트리는 계층 구조를 표현하거나 조건에 따라 데이터를 분기할 때 사용한다.

## 파일 시스템

파일 시스템은 폴더와 파일을 계층적으로 관리한다.

드라이브 또는 최상위 폴더가 루트가 되고, 그 아래에 폴더와 파일이 자식 노드로 연결된다.

```text
root
├─ documents
│  └─ report.md
└─ images
   └─ photo.png
```

특정 파일의 경로는 루트부터 자식 노드를 따라 내려가며 표현한다.

## 결정 트리

결정 트리는 조건에 따라 분기하면서 결과를 결정하는 구조다.

각 노드는 질문이나 조건을 나타내고, 간선은 조건에 대한 결과를 나타낸다.

```text
조건 확인
├─ 참 → 다음 조건
└─ 거짓 → 결과
```

분류와 회귀 문제에 사용할 수 있으며, 여러 조건을 순서대로 판단해 최종 결과에 도달한다.

## DOM Tree

HTML 문서는 태그의 중첩 관계에 따라 트리 구조로 표현된다.

```html
<html>
    <body>
        <h1>HTML</h1>
        <ul>
            <li>Java</li>
            <li>JavaScript</li>
        </ul>
    </body>
</html>
```

위 문서에서 `html`은 상위 노드이고, `body`, `h1`, `ul`, `li`는 중첩 관계에 따라 자식 노드가 된다.

브라우저는 이 구조를 DOM Tree로 구성하며, JavaScript는 각 노드에 접근해 내용을 변경하거나 이벤트를 연결한다.

## Huffman Tree

Huffman Tree는 데이터 압축에 사용하는 트리 구조다.

등장 빈도가 높은 데이터에는 짧은 코드를 부여하고, 빈도가 낮은 데이터에는 긴 코드를 부여한다.

이 방식을 사용하면 전체 데이터의 크기를 줄일 수 있다.

```text
빈도가 높음 → 짧은 코드
빈도가 낮음 → 긴 코드
```

문자별 코드 길이가 서로 다르며, 트리의 경로를 이용해 각 데이터를 구분한다.

## 데이터베이스 인덱스

데이터베이스는 빠른 검색을 위해 인덱스를 사용한다.

인덱스에는 트리 구조가 많이 사용되며, 대표적으로 B-Tree와 B+Tree가 있다.

트리의 분기 구조를 따라 탐색 범위를 줄이기 때문에 전체 데이터를 처음부터 확인하는 것보다 효율적으로 값을 찾을 수 있다.

## 알고리즘 선택 결정 트리

알고리즘을 선택할 때도 조건에 따라 적절한 자료구조를 찾는 결정 트리를 사용할 수 있다.

다음과 같은 조건을 순서대로 확인한다.

* 데이터의 순서가 중요한가
* 중복을 허용하는가
* 빠른 탐색이 필요한가
* 우선순위 처리가 필요한가
* 앞뒤 양쪽에서 데이터를 처리하는가

조건에 따라 `List`, `Set`, `Map`, `Stack`, `Queue`, `Deque`, `Tree` 등을 선택한다.

## 기억할 판단 기준

* 계층 관계를 표현해야 하면 트리 구조를 고려한다.
* 파일 시스템은 폴더와 파일을 트리 형태로 관리한다.
* 결정 트리는 조건을 따라 분기하며 결과를 결정한다.
* HTML 문서는 DOM Tree로 표현된다.
* Huffman Tree는 데이터 빈도에 따라 코드를 부여해 압축한다.
* 데이터베이스 인덱스에는 B-Tree와 B+Tree가 사용된다.
* 트리는 계층 표현뿐 아니라 탐색, 분류, 압축에도 활용된다.
